# 13장 실제 가격 자료와 개발용 미리보기 구분하기

이 장의 핵심은 가격을 많이 모으는 일이 아니다. 가격 한 건을 어떤 조건에서 확인했는지 기록하고, 공개해도 되는 자료와 개발자가 확인하는 자료가 섞이지 않게 만드는 일이다. 독자는 가상 자료 한 건으로 입력 검사와 읽기 전용 미리보기 구조를 배운다. 쇼핑몰 계정, 실제 주문, 실제 가격 수집은 필요하지 않다.

실습 결과는 두 갈래다. 기본 실습은 터미널에서 가상 입력을 검사한다. Android USB 연결을 준비한 독자는 같은 구조의 가상 기록을 개발용 화면에서도 읽는다. 어느 경로든 일반 놀이에는 자체 예시 상품 12개가 그대로 남는다.

## 13.1 가격의 출처·조건·확인 시간 기록하기

먼저 새 참고 코드를 만든다. 12장의 개인 연결값과 10장의 직접 작성한 코드는 해당 폴더에 남는다.

```bash
cd ~/market-book/kit
node start.mjs 13
cd work/ch13
npm --prefix scripts/database ci
npm --prefix apps/mobile ci
```

이 장도 11·12장과 같은 `479f6f5`의 전체 앱을 사용한다. 새로운 참고 폴더로 이동했으므로 의존성을 설치하며, 환경 파일은 자동 복사되지 않는다. 이 장의 기본 경로에는 Supabase 연결값이 필요 없다.

VS Code에서 다음 파일을 차례로 연다.

| 파일 | 읽을 부분 |
|---|---|
| `scripts/database/manual-observations.mjs` | 입력 필드 검사와 비공개 출력 만들기 |
| `supabase/migrations/20261112102641_manual_price_observations.sql` | 관측값의 제약 조건과 공개 제외 |
| `scripts/device/private-price-preview.mjs` | PC의 기록을 개발용 서버로 읽기 |
| `apps/mobile/src/features/catalog/real-price-preview.ts` | 앱에서 미리보기 응답 검사 |
| `apps/mobile/src/components/real-price-preview.tsx` | 별도 모달에 기록 표시 |

상품 정보와 관측값을 분리했던 11장을 떠올려 보자. 같은 상품도 날짜, 배송 지역, 로그인 상태, 행사 조건에 따라 보이는 금액이 달라질 수 있다. 기록을 다시 읽는 사람에게는 숫자 외의 설명이 필요하다.

| 기록 | 예시의 의미 |
|---|---|
| 출처 종류 | 사람이 확인한 `manual_observation` |
| 원본 상품 ID·URL | 어떤 페이지의 어떤 상품인지 구분 |
| 채널·매장 | 온라인 채널인지 특정 매장인지 구분 |
| 이름·단위 | 1개 가격과 묶음 가격을 혼동하지 않기 |
| 확인 시각 | 가격을 보았던 시점 |
| 행사 종류·조건 | 조건 없는 표시인지 추가 설명이 필요한지 |
| 재고 상태 | 확인하지 않았다면 `unknown` |
| 권한·공개 상태 | `unknown`과 `draft`에서 시작 |
| 로그인·배송 맥락 | 개인 정보를 쓰지 않고 확인 조건만 기록 |

확인하지 않은 값을 추측해 채우지 않는다. 매장 코드가 없으면 비워 두고, 재고를 확인하지 않았다면 모른다고 기록한다. 시간은 저장할 때 UTC 형식으로 쓰고 화면에서 읽기 좋은 형태로 바꾼다. `2026-11-12T10:00:00.000Z`의 끝에 있는 `Z`가 UTC 표시다.

## 13.2 실제 관측 가격과 놀이용 가격 규칙 이해하기

이 앱은 원 단위 정수를 사용한다. 1,234원을 `1234`로 저장하고 표시할 때 쉼표를 넣는다. 계산에 문자열 `"1,234원"`을 넣거나 부동소수점 금액을 섞지 않는다.

현재 구현의 `play_price_rule`은 `exact`다. 원본 가격과 놀이 가격이 같다는 뜻이다. 임의로 백 원 단위 반올림을 해 놓고 `exact`라고 기록하면 데이터의 설명과 실제 값이 어긋난다.

```text
source_price_krw = 1234
play_price_krw   = 1234
play_price_rule  = exact
```

입력 도구가 허용하는 정수 범위와 놀이에 쓰는 범위도 구분한다. 입력 도구는 PostgreSQL 정수에 들어가는 양수인지 검사한다. 공개 놀이 목록은 별도로 1원부터 10,000원까지의 상품을 받는다. 비싼 가격 기록이 문법상 올바르다고 해서 오늘의 놀이돈으로 살 수 있는 공개 상품이 되는 것은 아니다.

실제 가격을 보기 쉽게 바꾸는 기능을 추가한다면 새 규칙의 이름, 변환 방식, 표시 문구, 계산 검사를 함께 설계해야 한다. 이 책의 실습은 기존 `exact` 규칙을 유지한다.

## 13.3 수동 가격 자료의 입력값 검사하기

동봉 파일은 실제 판매 정보를 포함하지 않는 합성 자료다. 예시 URL은 입력 형식 검사를 위한 문자열이며 웹 요청을 보내지 않는다. 상품 이름도 검사용 가상 상품임을 표시한다.

저장소 루트인 `work/ch13`에서 실행한다.

```bash
cp ../../steps/13/manual-observation-demo.mjs .
node manual-observation-demo.mjs
```

파일의 입력 부분은 다음과 같다. 전체 코드는 복사한 파일에서 읽고 수정한다.

```js
const input = [{
  sourceProductId: '9999999999991',
  sourceUrl:
    'https://emart.ssg.com/item/itemView.ssg?itemId=9999999999991&siteNo=6001',
  name: '검사용 가상 상품',
  unitLabel: '가상 1봉',
  priceKrw: 1234,
  observedAt: '2026-11-12T10:00:00.000Z',
  availability: 'unknown',
  promotionType: 'none',
  priceBasis: 'displayed_item_total',
  notes: '책의 로컬 입력 검사만을 위한 가상 자료',
  loginContext: '로그인하지 않음',
  deliveryContext: '배송지를 선택하지 않음',
}];

// 날짜가 지나도 같은 검사가 되도록 검사 시계도 고정한다.
const options = { now: '2026-11-12T10:01:00.000Z' };
const result = prepareManualObservations(input, options);
```

`prepareManualObservations`는 파일을 읽거나 원격 DB에 쓰는 함수가 아니다. 전달받은 객체를 검사하고 정해진 구조의 결과를 돌려준다. 잘못된 입력이면 예외를 발생시킨다. 함수의 출력을 DB에 넣는 별도 작업과 입력 검사를 구분해야 한다.

정상 입력에서는 표에 `1234`, `manual_observation`, `unknown`, `draft`가 나타난다. 이어서 다음 세 문장이 출력되어야 한다. 표 테두리와 열 간격은 터미널마다 다를 수 있다.

```text
소수 가격: 거절
미래 관측: 거절
입력으로 공개 승인 추가: 거절
네트워크 요청·DB 적재·파일 저장: 수행하지 않음
```

첫 검사는 `priceKrw: 12.34`를 거부한다. 둘째는 검사 시계보다 미래의 관측 시각을 거부한다. 셋째는 허용된 입력 필드에 없는 `rights_status`를 끼워 넣어 공개 승인을 얻으려는 입력을 거부한다. 이 도구는 최신 24시간 안에 확인한 기록을 받도록 설계되어 있다. 오래된 고정 예시를 현재 시간으로 검사하면 실패하므로 실습에서는 입력 시각과 검사 시계를 함께 고정했다.

**직접 바꾸기.** 복사한 파일의 가격을 `2000`으로 바꾸고 실행한다. 표의 금액이 바뀌어도 권한과 공개 상태는 그대로여야 한다. 다음에는 입력 자체의 가격을 `0`으로 바꾼다. 이 경우 정상 결과를 만드는 첫 호출부터 실패하는 것이 맞다. 확인한 뒤 다시 양의 정수로 복원한다.

## 13.4 공개 승인 전에는 앱에 섞지 않는 구조 만들기

공개 제외는 화면의 버튼 하나를 숨기는 것으로 끝나지 않는다. 입력 도구, DB 정책, 공개 뷰가 각각 같은 경계를 지킨다.

```text
수동 입력
  → 필드·가격·시각 검사
  → 비공개 상품과 관측값
     is_active: false
     rights_status: unknown
     publication_state: draft

일반 앱
  → public.play_catalog
  → 공개 조건을 통과한 자체 예시 상품 12개

개발용 미리보기
  → 별도 로컬 기록
  → USB로 연결한 개발 화면에서 읽기만
```

이것은 현재 구현을 설명한 흐름도이며 프로그램 화면 캡처가 아니다. 공개 뷰는 단순히 최신 가격을 전부 반환하지 않는다. 공개 승인 상태, 상품 활성 상태, 유효 기간과 놀이용 범위 등의 조건을 통과한 값만 제공한다. 수동 입력 도구의 성공은 자료의 재배포 승인과 다르다. DB의 `manual_observation_is_private` 제약은 관리자라도 수동 관측을 `app_approved`·`published`로 바꾸지 못하게 한다. 적법한 이용권한과 승인 출처를 확보한 경우에는 그 출처에 맞는 새 관측으로 처리하며, 기존 비공개 관측의 상태값만 바꾸는 방식으로 공개하지 않는다.

11장의 SQL 검사를 다시 실행하면 이 경계도 확인할 수 있다.

```bash
npm --prefix scripts/database test
```

실제 저장소는 관측값 원문과 개발 검사 산출물을 공개 코드와 분리한다. 책에는 개인 배송지, 로그인 계정, 인증값, 실제 비공개 관측 원문을 실어서는 안 된다. 자기 프로젝트에서 같은 기능을 만들 때도 가상 예시와 개인 기록을 서로 다른 파일에 둔다.

## 13.5 ADB 설치 후 USB 연결 상태 확인하기

이 절부터는 Android 실제 화면을 보고 싶은 독자를 위한 선택 실습이다. 기본 입력 검사만 마쳐도 이후 장을 진행할 수 있다. USB 실습을 한다면 휴대전화에 이 책의 Expo SDK와 맞는 Expo Go가 설치되어 있어야 한다.

Android 공식 [SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)에서 Windows용 ZIP을 받아 사용자 폴더의 `market-book/tools` 아래에 푼다. 결과가 다음처럼 되도록 한다.

```text
market-book/
  tools/
    platform-tools/
      adb.exe
  kit/
```

Android의 개발자 옵션에서 USB 디버깅을 켠다. 메뉴 이름과 개발자 옵션을 여는 방법은 제조사에 따라 다르다. USB 데이터 전송이 가능한 케이블로 한 대만 연결하고 화면 잠금을 푼다. 휴대전화에 PC의 디버깅을 허용할지 묻는 창이 나오면, 자신의 PC인지 확인하고 허용한다.

Git Bash에서 실행한다.

```bash
ADB="$HOME/market-book/tools/platform-tools/adb.exe"
"$ADB" devices
```

두 번째 줄의 상태를 읽는다. 아래의 기기 표시는 설명용으로 바꾼 값이다.

| 상태 | 의미와 다음 행동 |
|---|---|
| `기기표시 device` | ADB 명령을 받을 준비가 됨 |
| `기기표시 unauthorized` | 휴대전화에서 디버깅 허용 확인 |
| `기기표시 offline` | 케이블과 연결을 점검한 뒤 다시 조회 |
| 제목만 출력 | 케이블, USB 모드, 드라이버, 디버깅 설정 확인 |
| 두 대 이상 | 이번 실습에 쓰는 한 대만 남기기 |

`device`라는 단어는 화면 잠금이 풀렸다는 증명까지 하지는 않는다. 직접 잠금을 풀고 앱을 조작할 수 있는 상태인지 확인한다. 기록을 공유할 때는 기기 식별자를 가린다.

## 13.6 USB 연결 기기에서 읽기 전용으로 미리보기

동봉 실행기는 실제 기록 대신 방금 만든 것과 같은 가상 구조를 사용한다. Supabase나 쇼핑몰에 접근하지 않고, 기존 미리보기 파서와 서버를 호출한다. 제목은 `[가상 실습] 가격 기록`, 가격은 1,234원이다.

먼저 기기와 서버를 쓰지 않는 구조 검사부터 한다.

```bash
cd ~/market-book/kit/work/ch13
cp ../../steps/13/start-preview-demo.mjs .
node start-preview-demo.mjs --check
```

`가상 미리보기 형식: 1개 통과. 기기·서버·파일 변경 없음.`가 나오면 실제 USB 실행을 준비한다. 이전 Expo 터미널은 Ctrl+C로 종료한다. 이 실행기는 포트 8092와 8093을 사용하며, 다른 프로그램이 사용하고 있으면 임의로 종료하지 않고 실패한다.

```bash
BOOK_ADB="$(cygpath -w "$HOME/market-book/tools/platform-tools/adb.exe")" \
node start-preview-demo.mjs
```

Git Bash 경로를 Windows 프로그램이 읽을 수 있게 `cygpath -w`로 바꾼다. 명령은 자신의 PC에 설치한 `adb.exe`를 명시적으로 사용한다.

실행기는 가상 기록을 새 `.artifacts/catalog/book-preview-숫자.json`에 저장하고 PC의 루프백 주소에 서버를 연다. USB 역방향 연결로 기기에서 그 서버를 읽게 하며 Expo Go를 연다. 앱에서 다음 순서로 확인한다.

1. **예시 상품으로 바로 놀이하기**를 누른다.
2. 자체 예시 상품 12개가 나오는지 확인한다.
3. **실제 가격 미리보기 · 개발용**을 연다.
4. `[가상 실습] 가격 기록` 한 건과 1,234원을 읽는다.
5. 확인 시각과 자료를 읽은 시각을 구별한다.
6. **닫기**로 일반 놀이에 돌아간다.

화면 제목과 출처 설명은 기존 개발용 컴포넌트를 그대로 사용한다. 이번 자료는 합성 자료이므로 화면의 “DB에서 가져온 시간”은 실행기가 만든 가상 스냅샷의 시각이며 실제 DB 조회를 의미하지 않는다. 출처 URL 역시 방문하거나 가격을 확인한 증거가 아니다. 실제 조회를 했다고 기록하지 않는다.

미리보기를 닫은 뒤 사과 두 개와 우유 한 개를 담아 5,500원을 확인한다. 가상 기록은 장바구니 상품이 아니므로 합계에 섞이지 않아야 한다. 실습을 마치면 터미널에서 Ctrl+C를 누른다. 실행기가 자신이 시작한 Expo, 미리보기 서버, 이번에 추가한 USB 포트 연결을 정리한다.

| 증상 | 확인할 곳 |
|---|---|
| `BOOK_ADB` 경로 오류 | `adb.exe` 파일 위치와 `cygpath -w` 결과 |
| 포트 사용 중 | 기존 실습 터미널을 정상 종료한 뒤 재실행 |
| 개발 서버 준비 실패 | `apps/mobile`의 `npm ci` 완료 여부 |
| Expo Go가 열리지 않음 | 설치 여부, 호환 SDK, 잠금·USB 승인 |
| 미리보기 연결 오류 | 실행기 터미널 유지, USB 케이블, 서버 종료 여부 |

원고 작성 과정에서는 가상 구조 검사를 실행했다. 이 책에 동봉한 USB 실행기 자체의 기기 실행 성공을 과거 실기기 기록으로 대신하지 않는다. 독자는 위 여섯 단계의 실제 결과를 자신의 검사 기록에 남긴다.

## 13.7 미리보기 상품을 일반 놀이와 분리하기

미리보기는 `Modal` 안에서 기록을 보여 준다. 여기에 있는 가격은 일반 상품 목록을 만드는 `CatalogLoader`에 전달하지 않는다. 수량 버튼이나 결제 콜백도 없다. 앱 내부에서 읽기 전용이라는 말은 이 연결 관계로 확인한다.

VS Code의 전체 검색에서 `PrivatePricePreview`를 찾는다. App의 개발 모드 분기와 별도 컴포넌트가 연결되어 있다. 이어서 `readRealPricePreviewConfig`를 찾으면 개발 모드, 명시적인 미리보기 플래그, 실행마다 달라지는 접근 토큰이 모두 필요함을 볼 수 있다. 로컬 서버 주소도 정해진 루프백 경로로 제한한다.

일반 빌드에 공개 환경 변수를 넣는 것만으로 비밀 자료를 안전하게 보관할 수는 없다. `EXPO_PUBLIC_` 값은 클라이언트 번들에 들어간다. 미리보기 토큰은 이번 개발 세션의 접속 제어용이며 장기 비밀 키가 아니다. 입력 원문과 토큰을 스크린샷, 책, 오류 보고서에 복사하지 않는다.

**직접 추적하기.** 일반 놀이의 상품 목록을 만드는 함수와 미리보기에서 가격을 표시하는 함수를 각각 한 개씩 적는다. 그 사이에 장바구니로 데이터를 넘기는 호출이 있는지 찾아본다. 현재 참고 코드에는 그런 호출이 없다.

## 13.8 현재 가격 기능의 범위와 공개 전 검토 항목

현재 기능은 사람이 확인한 기록을 검증하고 개발용으로 읽는 범위다. 실시간 가격 조회, 자동 수집, 재고 보장, 일반 사용자에게 실제 가격을 공개하는 기능은 포함하지 않는다. 지금 가진 코드만으로 공개 가격 서비스가 완성되었다고 해석하지 않는다.

실제 자료를 공개하는 별도 작업을 진행한다면 자료 제공 조건과 재배포 권한, 상품·행사·배송 조건 표시, 갱신과 만료, 오류 수정, 공개 철회 방법을 먼저 정한다. 이 책에서는 그 권한을 얻었다고 가정하거나 비공개 기록을 공개 상태로 바꾸는 명령을 제공하지 않는다. 자체 예시 12개로 모든 놀이와 설치 실습을 마칠 수 있기 때문이다.

장 마무리 기록에는 세 문장을 남긴다. “가상 입력 검사 결과”, “USB 선택 실습 수행 여부”, “일반 놀이가 자체 예시 12개와 합계 5,500원을 유지했는지”다. 실제 기기 실습을 하지 않았다면 수행하지 않았다고 적는다. 다음 장은 가격 자료의 범위를 넓히지 않고, 네트워크가 느려도 이 자체 예시로 놀이를 시작하는 흐름을 다룬다.
