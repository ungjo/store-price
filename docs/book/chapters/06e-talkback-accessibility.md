## 수정 전에 실제로 확인한 문제

기존 화면에서 사과의 **담기**에 접근성 포커스를 놓고 활성화하자 새로 생긴 **한 개 빼기**로 포커스가 이동했다. 계속 담으려는 사용자가 의도하지 않은 버튼에 놓이는 문제다. `.artifacts/device/talkback-probe-20261116/`의 `baseline-19.json`에는 `product-sample-apple-add`, `baseline-added.json`에는 `product-sample-apple-decrease`가 포커스된 것으로 기록됐다. 발화 표시 화면에서도 ‘사과 한 개 빼기, 버튼’을 확인했다.

접근성 이름이 코드에 존재한다는 사실만으로 이 문제를 찾을 수는 없었다. 실제 TalkBack을 켠 상태에서 스와이프·탭으로 이동하고, 활성화 뒤 어떤 요소에 포커스가 남는지 확인해야 했다.

## 앱에서 바꾼 읽기 정보와 포커스

수량이 0개에서 1개가 되어도 **담기** 버튼의 부모·키·실제 버튼을 유지한다. 수량에 따라 다른 버튼 트리를 만드는 대신 같은 버튼의 이름과 모양을 바꿔 첫 담기 뒤 포커스가 사라지지 않게 한다. 버튼의 현재 값에는 ‘현재 1개 담김’처럼 수량을 전달하고, 9개일 때는 최대 수량 안내와 비활성 상태를 함께 전달한다. 마지막 한 개를 빼서 빼기 버튼이 사라질 때는 남아 있는 담기로 포커스를 돌린다.

분류의 ‘선택됨’은 이름에 반복해서 넣지 않고 선택 상태 속성으로 전달한다. 화면의 선택 표시와 실제 선택 상태는 유지한다. TalkBack이 이름과 상태를 각각 읽을 때 중복 안내가 생긴 관측을 반영한 변경이다. 이름·역할·상태·값을 분리하는 기준은 [React Native 접근성 안내](https://reactnative.dev/docs/accessibility)를 따른다.

정답 후 사라지는 확인 버튼의 포커스는 결과 안내로 옮기고, 영수증은 제목부터 읽도록 한다. 새 놀이도 화면 시작 위치로 돌아갈 수 있게 포커스를 관리한다. 공통 포커스 함수는 화면 읽기 사용 여부를 확인한 뒤 다음 프레임에 현재 native 참조로 이벤트를 보낸다. 새 요청이 오거나 화면이 사라지면 이전 예약을 취소해 뒤늦은 포커스 이동을 막는다. 정답 안내·영수증 제목에는 같은 내용을 포커스와 live 알림으로 중복 전달하지 않도록 조정한다.

추가 진단에서 키보드 닫힘 안내가 채점 발화를 덮는 문제가 보여, 정답 안내의 자동 포커스에 `afterKeyboardHides` 옵션을 적용했다. `Keyboard.isVisible()`이 참이면 `keyboardDidHide`를 받은 뒤 다음 프레임에 결과로 이동하고, 이미 닫혔으면 기존처럼 다음 프레임을 사용한다. 숨김 이벤트와 구독 사이의 경합·중복 이벤트를 처리하고, 새 입력이나 취소·화면 종료 뒤 오래된 요청이 포커스를 빼앗지 않도록 리스너와 예약 프레임을 정리한다. 이후 다시 풀기 뒤 입력칸으로 복귀할 때도 이 처리를 재사용했다. 이 변경의 실제 전체 효과는 후속 진단으로 확인한다.

## TalkBack을 유지하면서 관찰하는 방법

이번 기기에서는 일반 ADB 입력만으로 앱 안의 TalkBack 제스처 동작을 확인할 수 없었다. 임시 터치 입력 장치인 `uinput`으로 스와이프·탭을 전달하고 입력 프로세스가 종료되면 장치를 해제한다. 단순히 버튼의 `onPress`를 직접 호출한 결과를 TalkBack 조작 성공으로 대신하지 않는다.

화면 정보를 읽는 Java 도우미는 접근성 서비스를 억제하지 않는 `FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES` 값 1로 연결하고 실제 연결 플래그도 확인한다. 허용한 앱·TalkBack·숫자 키보드의 화면 정보만 수집한다. 관찰 도구가 TalkBack을 멈춘 상태로 검사를 통과시키지 않기 위한 구분이다. [Android UiAutomation 안내](https://developer.android.com/reference/android/app/UiAutomation#FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES)

Samsung 배포판 로그에서는 발화 내용을 얻지 못해 **Speech output overlay**를 검사 중에만 켠다. 화면 하단의 발화 표시 영역을 찾아 Windows 한국어 OCR로 읽고, 접근성 포커스·이름·상태와 별도로 대조한다. Android 공식 테스트 안내도 발화 출력 표시를 TalkBack 검사에 활용할 수 있다고 설명한다. [Android 접근성 테스트](https://developer.android.com/guide/topics/ui/accessibility/testing)

따라서 이 검사의 근거는 실제 제스처 뒤의 동작, native 접근성 정보, TalkBack 발화 표시의 텍스트다. 스피커 음성을 녹음하거나 사람이 발음을 청취한 근거로 확대하지 않는다. 원본 화면·음성 표시 자료는 `.artifacts/device/`에 두고 개인 화면 이미지나 전체 덤프를 커밋하지 않는다.

## 설정을 기록하고 복구하기

기준 점검에서 원래 서비스 목록은 미설정(`null`), 접근성 사용 값은 0, 발화 표시 false, 관찰용 필터 0, 충전 중 화면 유지값 0이었다. 기준 화면 관찰 뒤 이 값들의 복구를 확인했다. 정식 검사도 시작할 때의 상태를 기록하고 검사 종료·실패 뒤 복구 여부를 확인한다. TalkBack을 무조건 꺼 두는 것을 모든 사용자의 기본값으로 간주하지 않는다.

실제 제스처·관찰 도구와 임시 화면 유지 설정도 검사 실행의 관리 대상이다. 복구 확인이 없는 실행을 최종 통과나 자동 커밋으로 처리하지 않는다.

## 실행 명령

저장소 루트의 Git Bash에서 TalkBack 부분 진단을 실행한다.

```bash
node scripts/device/verify.mjs --talkback-only
```

부분 진단은 전체 성공 보고서나 커밋을 만들지 않는다. 기존 놀이 회귀와 TalkBack을 함께 확인하고 기록·커밋하려면 다음 명령을 사용한다.

```bash
node scripts/device/verify.mjs --talkback --message "feat: TalkBack 장보기와 영수증 접근성 개선"
```

TalkBack은 21개 확인 지점을 통과했고 새 놀이의 `market-title` 포커스와 표시 상태도 확인됐다. 실제 발화 표시 화면에는 ‘오늘은 무엇을’과 ‘사 볼까요?, 제목’이 두 줄로 보였으나 OCR은 첫 줄을 ‘오느으 어 으’로 잘못 읽어 마지막 발화 대조에서 실패했다. 앱의 제목 이동 실패와 구분해 OCR 전처리를 보완하고 같은 기준으로 재검사한다. TalkBack 관련 설정과 화면 유지값 0의 복구를 모두 확인했으며 실행 전체는 실패, 커밋은 없음으로 기록했다. 원본은 `.artifacts/device/20261116T104707001Z-ecfa99f5/`에 보존한다.

빈 장바구니 부분 진단 `.artifacts/device/talkback-empty-check-1794828045716/`에서는 앱을 새로 열고 실제 TalkBack 순서 탐색으로 `cart-empty`에 도착했다. 포커스·표시 상태와 ‘아직 장바구니가 비어 있어요’라는 native 정보를 확인한 한 지점의 결과다. 당시 발화 OCR은 별도 보완 중이어서 통과 근거에 포함하지 않았다. TalkBack 설정 복구는 확인했으며 임시 화면 유지값 7은 후속 전체 검사 전에 원래 값 0으로 복구할 대상으로 남겼다.

OCR 전처리는 85~255 범위를 단일 회색조로 선형 반전해 한글 획과 숫자·쉼표를 보존하도록 수정했다. 기대 문구, 숫자 경계, 텍스트 정규화 기준은 바꾸지 않았다. 관찰 도우미 12개와 OCR 검사 13개가 통과했고 저장 PNG 18개 모두 기존 기대 문구 대조를 통과했다. 새 놀이 제목 ‘오늘은 무엇을 사 볼까요? 제목’, 첫 담기의 합계 ‘1,500원’, 새 빈 장바구니 화면의 ‘아직 장바구니가 비어 있어요’도 포함한다. 근거는 `.artifacts/device/ocr-title-probe/grayscale-regression.json`에 남기며 기대 범위 밖의 OCR 오류는 원문 그대로 보존한다. 이 결과는 저장 화면의 인식 회귀 검사이며 정식 TalkBack 23지점 전체 재실행을 대신하지 않는다.

최종 전체 실행 전 코드와 원고를 고정한다. 정식 `--talkback` 실행은 기존 놀이 회귀와 새 놀이 제목의 포커스·발화를 포함한 23개 확인 지점을 검사한다. 최종 상태는 [자동 검증 보고서](../verification/latest-android.md)의 검사 시작 HEAD `0e008b9`, 실제 실행 ID, TalkBack 동선과 설정 복구 결과로 확인한다. 앞 단계 태블릿 APK의 PASS나 일부 확인 지점의 성공은 이번 접근성 전체 검증의 성공 근거가 아니다.
