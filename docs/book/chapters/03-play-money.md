# 03장. 놀이돈 안에서 살펴보기

날짜: 2026-11-11

시작 기준: `6009317` — 장바구니 담기·수량 조절·합계 기능 구현. 사용자가 직접 커밋하고 GitHub 업로드까지 완료했다.

이번 장의 코드 커밋: `281a5e9` — 사용자가 갤럭시 기본 동작 확인 후 직접 커밋하고 GitHub 업로드를 완료했다(2026-11-11).

커밋 메시지: `feat: 놀이돈 예산과 남을 돈·부족한 돈 표시 구현`

> 현재 기록: 기본 놀이돈과 예산 안내를 구현하고 단위 테스트 17개·전체 타입 검사·ESLint·Android·iOS·웹 번들 검사를 통과했다. 브라우저 검증에 이어 2026-11-11에 사용자가 갤럭시에서 기본 예산·잔액·딱 맞음·초과·수량 감소 후 회복·전체 비우기·새로고침 초기화를 확인해 이번 단계의 기본 동작 검증을 마쳤다. iPhone 실기기와 화면 읽기 기능은 아직 확인하지 않았다.

## 한 번에 한 가지 배우기

장바구니에 물건을 담는 다음 단계로, 정해진 놀이돈 안에서 살 수 있는지 보여준다. 첫 예산은 **10,000원으로 고정**했다. 예산을 고르는 화면은 추가하지 않았다. 먼저 합계가 바뀔 때 남을 돈과 부족한 돈이 정확하게 바뀌는지 확인하기 위해서다.

이번 화면은 돈을 실제로 내기 전의 예산 안내다. “남을 돈”은 지금 장바구니 그대로 산다면 예산에서 남는 금액이다. 실제로 낸 돈에서 물건값을 뺀 거스름돈이나 거스름돈 맞히기 퀴즈는 후속 단계에서 다룬다.

가격은 앞 장과 같은 자체 예시 가격이다. 실제 이마트 가격 수집과 DB 연결은 여전히 이후 단계다.

## 구현한 화면

상품 목록 위에 “오늘의 놀이돈 10,000원” 카드를 추가했다. 하단의 기존 장바구니 합계에는 예산과 비교한 결과를 함께 보여준다.

| 장바구니 합계 | 하단에 보여주는 결과 |
| --- | --- |
| 0원 | 남을 돈 10,000원 · 놀이돈 안에서 장을 봐요. |
| 5,500원 | 남을 돈 4,500원 · 이대로 사면 남을 돈이에요. |
| 10,000원 | 남을 돈 0원 · 놀이돈에 딱 맞아요! |
| 13,500원 | 부족한 돈 3,500원 · 물건을 조금 빼 볼까요? |

예산을 넘겨도 상품을 담는 것은 허용한다. 아이가 부족한 금액을 보고 물건을 빼며 선택을 바꿔 볼 수 있게 하기 위해서다. 품목당 최대 9개라는 기존 장바구니 규칙은 그대로 적용한다.

남을 돈과 부족한 돈은 색뿐 아니라 글자로도 구분한다. 화면 읽기용 접근성 이름에도 장바구니 수량·합계·예산·남거나 부족한 금액·안내 문장을 포함했다. 접근성 이름을 코드에 넣은 것과 실기기의 화면 읽기 기능으로 검증한 것은 구분하며, 실제 화면 읽기 검증은 아직 남아 있다.

## 남을 돈을 따로 저장하지 않은 이유

장바구니는 `useReducer`로 상태를 관리하지만 예산 계산에 새 상태는 추가하지 않았다. 매번 현재 합계에서 계산하면 상품 수량 감소·품목 삭제·전체 비우기를 할 때 잔액을 따로 고치는 작업이 필요하지 않다.

`src/features/budget/budget.ts`의 기본 금액은 `STARTING_BUDGET_KRW = 10000`이다. `getBudgetSummary(totalPriceKrw, budgetKrw)`는 합계와 예산으로 다음 값을 반환한다.

| 반환값 | 의미 |
| --- | --- |
| `remainingKrw` | 예산 안에서 남을 금액. 예산을 넘으면 0 |
| `shortfallKrw` | 부족한 금액. 예산 안이면 0 |
| `status` | 예산 안이면 `within`, 딱 맞으면 `exact`, 넘으면 `over` |

계산은 원 단위 정수의 차이로 처리한다.

```text
차이 = 예산 - 장바구니 합계
남을 돈 = 차이와 0 중 큰 값
부족한 돈 = -차이와 0 중 큰 값
```

부족한 금액을 음수 잔액으로 표시하지 않고 별도 값으로 반환한다. 화면에서 아이에게 “남을 돈”과 “부족한 돈”을 분명하게 설명하기 위해서다. 이 이유와 파생값으로 계산하는 이유를 핵심 코드의 한국어 주석으로 남겼다.

함수는 두 번째 인자로 다른 예산을 받을 수 있어 테스트에서 5,000원 예산도 확인했다. 현재 앱 화면은 인자를 생략해 기본 10,000원만 사용하며, 예산 선택 기능이 구현됐다는 뜻은 아니다.

## 테스트를 기존 장바구니와 함께 실행하기

예산 테스트 8개를 추가했다. 0원·5,500원·10,000원·13,500원이라는 경계와 대표 금액을 검사하고, 기존 장바구니 reducer를 사용해 상품을 빼거나 비웠을 때 파생 잔액이 회복되는지도 검사했다.

| 확인 내용 | 결과 |
| --- | --- |
| 아무것도 담지 않음 | 10,000원 남음 |
| 5,500원 담기 | 4,500원 남음 |
| 10,000원 담기 | 딱 맞음, 남을 돈과 부족한 돈 모두 0 |
| 13,500원 담기 | 3,500원 부족 |
| 초과 상태에서 사과 수량 감소 | 부족한 돈이 줄고, 합계 9,000원에서 1,000원 남음 |
| 초과 상태에서 한 품목 전체 삭제 | 남은 상품의 합계로 잔액 회복 |
| 초과 상태에서 장바구니 전체 비우기 | 10,000원 전부 회복 |
| 함수에 5,000원 예산 전달 | 남음·딱 맞음·부족함을 새 예산 기준으로 계산 |

추가 패키지는 설치하지 않았다. 앞 장에서 준비한 Node 테스트 도구를 그대로 사용했다. `package.json`의 `test` 명령에는 두 테스트 파일 경로를 명시해 새 기능과 기존 장바구니를 함께 검사하도록 했다.

```bash
node --experimental-strip-types --test src/features/cart/cart.test.ts src/features/budget/budget.test.ts
```

예산 파일만 검사할 때 실제 실행한 명령은 다음과 같다. **8개 모두 통과**했다.

```bash
node --experimental-strip-types --test src/features/budget/budget.test.ts
```

전체 검증은 `apps/mobile` 폴더에서 다음 명령으로 실행했다.

```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run export:check
```

기존 장바구니 9개와 예산 8개를 합친 **17개 테스트가 모두 통과**했다. 타입 검사와 ESLint도 통과했다. Node 테스트의 `MODULE_TYPELESS_PACKAGE_JSON` 경고는 앞 장과 동일한 모듈 자동 판별 안내이며, 테스트 실패는 아니었다.

## 갤럭시 실기기 확인 기록

2026-11-11에 사용자가 오늘의 놀이돈 10,000원이 보이고, 사과 2개와 우유 1개를 담으면 합계 5,500원·남을 돈 4,500원이 정상 표시된다고 보고했다. 이로써 기본 예산과 예산 안에서의 잔액 표시를 실기기에서 확인했다.

이어서 사과를 한 개 더 담고 식빵 한 봉을 추가하도록 안내했다. 사용자는 총 5개·10,000원과 남을 돈 0원이 표시되고 “놀이돈에 딱 맞아요!” 안내도 보인다고 보고했다. 다음 확인을 위해 상품은 그대로 담아 두었다.

같은 날 사용자는 당근 1개를 더 담으니 총 6개·11,000원과 부족한 돈 1,000원이 표시되고 “물건을 조금 빼 볼까요?” 안내도 보인다고 보고했다. 상품은 다음 확인을 위해 그대로 두었다. 이로써 예산 초과 금액과 안내를 실기기에서 확인했다.

이어서 사용자는 당근을 빼면 총 5개·10,000원과 남을 돈 0원, 사과를 빼면 총 4개·8,500원과 남을 돈 1,500원이 표시된다고 보고했다. 안내 문구도 각각 “놀이돈에 딱 맞아요!”와 “이대로 사면 남을 돈이에요.”로 예상대로 바뀌었다고 확인했다. 이로써 초과 상태에서 수량을 줄여 딱 맞음과 예산 안 상태로 돌아오는 동작을 실기기에서 확인했다.

같은 날 사용자는 장바구니 비우기를 누르면 0개·0원과 남을 돈 10,000원이 표시되고, 장바구니가 비었다는 안내와 “놀이돈 안에서 장을 봐요.” 문구도 보인다고 보고했다. 이로써 전체 비우기 후 예산이 모두 남는 상태로 돌아오는 동작을 실기기에서 확인했다.

마지막으로 사과 1개를 담은 뒤 PC의 Expo 개발 서버 터미널에서 r을 눌러 앱을 새로고침하도록 안내했다. 사용자는 새로고침 후 0개·0원과 남을 돈 10,000원으로 돌아오고, 장바구니가 비었다는 안내와 사과의 담기 버튼도 보인다고 보고했다. 장바구니를 메모리에만 보관하는 현재 단계에서 초기화는 의도한 동작이며, 이를 실기기에서 확인했다.

이로써 이번 놀이돈 예산 단계의 갤럭시 기본 동작 확인을 마쳤다. 이후 사용자가 구현과 검증 기록을 `281a5e9`로 직접 커밋하고 GitHub 업로드를 완료했다. 커밋·태그·업로드를 자동으로 수행하지 않았다.

## 기본 예산 확인을 재현하는 순서

기존 Expo 개발 서버가 켜져 있다면 그 터미널에서 `r`을 눌러 갤럭시 화면을 새로고침한다. 장바구니는 메모리 상태이므로 새로고침 뒤 비워지는 것이 정상이다.

1. 화면 위에 “오늘의 놀이돈 10,000원”이 보이는지 확인한다.
2. 사과 2개와 우유 1개를 담는다.
3. 하단에 총 3개·5,500원과 “남을 돈 4,500원”이 보이는지 확인한다.

개발 서버가 꺼져 있다면 프로젝트 루트에서 연 Git Bash에 다음 명령을 입력하고 갤럭시 Expo Go로 QR을 연다.

```bash
cd apps/mobile
npm start
```

기본 예산·잔액 표시·예산에 딱 맞는 상태·부족한 돈 안내·수량 감소 후 회복·전체 비우기·새로고침 뒤 예산 복원의 사용자 확인과 `281a5e9` 커밋·업로드를 마쳤다. 다음은 [낼 놀이돈 선택](03a-payment-selection.md)을 작은 단계로 구현한다. 거스름돈 맞히기는 그 이후에 다룬다.
