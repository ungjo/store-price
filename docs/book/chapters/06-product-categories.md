작업일: 2026-11-15. 시작 커밋은 `4fbe035`이며 사용자가 GitHub 업로드를 확인했다. 이번 목표는 분류별 상품 찾기와 예시 상품 확장이다. 앞 단계에서 검증한 설치형 APK의 인터넷 없는 첫 실행과 이번 코드의 검사 결과를 구분한다.

## 상품과 분류

기존 6개 상품의 ID·이름·규격·가격·전체 목록 순서를 유지하고, 다음 6개를 뒤에 추가한다. 모두 직접 만든 연습용 가격이며 실제 이마트·SSG 판매 가격이 아니다.

| 분류 | 상품과 가격 | 개수 |
| --- | --- | --- |
| 과일·채소 | 사과 1,500원, 당근 1,000원, 바나나 3,500원, 오렌지 1,800원, 포도 4,000원, 오이 800원 | 6 |
| 유제품·달걀 | 우유 2,500원, 달걀 2,000원, 요구르트 1,200원, 치즈 2,000원 | 4 |
| 빵·간식 | 식빵 3,000원, 크래커 1,500원 | 2 |

화면에는 전체와 세 분류의 선택 버튼·상품 수를 표시한다. 분류를 바꾸는 동작은 보이는 상품 목록만 바꾼다. 장바구니 계산은 항상 처음 불러온 전체 목록을 기준으로 한다. 따라서 다른 분류로 이동해도 담은 상품이 사라지거나 합계가 줄지 않는다. 선택한 놀이돈과 풀던 문제도 그대로 유지한다.

상품 수량이나 낼 돈을 바꿀 때만 기존 규칙에 따라 퀴즈를 초기화한다. 영수증에서 다시 장보기를 선택하면 빈 장바구니·놀이돈 10,000원·전체 분류로 시작한다. 원격 목록은 다시 조회하고, 내장 예시는 같은 목록을 사용한다.

## DB와 앱의 같은 기준

DB의 `category_id`와 앱의 `categoryId`는 `produce`, `dairy-eggs`, `bakery-snacks` 세 값으로 연결한다. 분류가 지정되지 않은 비공개 자료는 그대로 보관한다. 공개 뷰는 지정된 분류와 기존 가격 공개 조건을 모두 만족하는 행만 반환한다. 앱은 알 수 없거나 빠진 분류를 포함한 응답을 불완전한 목록으로 표시하지 않고 오류 처리한다.

새 마이그레이션에서 분류 열·제약과 공개 뷰의 열을 추가하고, 기존 예시의 분류와 새 예시를 한 트랜잭션으로 적용한다. 예전 마이그레이션을 고쳐 이미 적용된 DB 이력을 바꾸지 않는다. 새 프로젝트의 `seed.sql`도 같은 12개를 만든다. 이미 저장된 승인·활성 상태나 가격 관측 사실을 반복 실행으로 덮어쓰지 않는지 로컬 PostgreSQL 검사에서 확인한다.
