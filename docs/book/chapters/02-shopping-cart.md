## 이번 단계의 목표

상품 가격을 읽는 화면에 상품 담기와 수량 조절을 더한다. 사과 2개와 우유 1개를 담았을 때 총 3개, 5,500원이 되는 과정을 아이가 화면에서 확인하게 만든다. 가격은 여전히 직접 만든 연습용 예시이며 실제 이마트 가격이 아니다.

같은 화면에 다음 기능을 구현했다.

- 상품 카드에서 물건을 담고 `+`와 `−`로 수량을 조절한다.
- 한 품목은 최대 9개까지 담는다. 1개에서 하나를 빼면 해당 상품이 장바구니에서 사라진다.
- 상품 목록 아래 장바구니에서 담은 상품, 수량, 품목별 금액을 본다.
- 한 상품을 모두 빼거나 장바구니 전체를 비운다.
- 화면 아래에는 총수량과 총액을 고정해, 목록을 움직여도 합계를 볼 수 있게 한다.

화면 이동과 실제 결제는 이 단계에 포함하지 않는다. 장바구니는 앱 메모리에만 저장하므로 앱을 새로고침하거나 다시 시작하면 비워진다. DB나 기기 저장소에 보관하는 기능은 아직 없다.

## 상태와 계산 규칙을 화면에서 분리하기

장바구니 상태에는 상품의 ID와 수량만 저장한다. 상품명과 단가는 기존 상품 목록에서 가져온다. 같은 가격을 여러 곳에 복사해 두면 한쪽만 바뀌었을 때 화면과 합계가 달라질 수 있기 때문이다.

```typescript
// 상품 정보는 목록에 두고, 장바구니에는 담은 수량만 보관합니다.
const cart = {
  'sample-apple': 2,
  'sample-milk': 1,
};
```

`src/features/cart/cart.ts`에는 두 가지 역할을 분리했다.

| 함수 | 역할 |
| --- | --- |
| `createCartReducer(catalog)` | 등록된 상품 목록을 받아 담기·빼기·삭제·비우기를 처리하는 함수를 만든다. |
| `getCartSummary(state, catalog)` | 상품별 가격과 수량을 곱해 총수량·총액·상품 종류 수를 계산한다. |

reducer는 이전 상태와 동작을 받아 다음 상태를 반환한다. `add`는 하나 담기, `decrease`는 하나 빼기, `remove`는 해당 품목 전체 삭제, `clear`는 장바구니 전체 비우기다.

원본 객체를 수정하지 않고 새 객체를 반환하도록 작성했다. 목록에 없는 상품 ID와 이미 없는 상품을 빼는 동작은 무시한다. 수량이 0이 된 상품은 키도 삭제한다. 이 규칙은 버튼이 여러 곳에 생겨도 한 함수에서 유지할 수 있다.

화면에서는 React의 `useReducer`로 이 규칙을 연결한다. 버튼이 동작을 전달하면 다음 상태로 화면과 합계를 함께 갱신하는 구조다. [React useReducer 공식 문서](https://react.dev/reference/react/useReducer)

가격은 원 단위 정수로 계산한다. 예시 상품 사과의 단가 1,500원에 수량 2를 곱하면 3,000원이고, 우유 1개 2,500원을 더하면 5,500원이다. 화면에 쉼표를 붙이는 형식과 계산에 사용하는 숫자를 분리한다.

핵심 코드에는 등록 상품만 받는 이유, 원본 상태를 보존하는 이유, 0개 품목을 삭제하는 이유를 한국어 주석으로 남겼다.

## 작은 테스트로 먼저 확인하기

화면에서 여러 번 눌러 보기 전에 장바구니의 계산과 수량 규칙을 검사했다. 테스트에서는 사과 1,500원, 우유 2,500원의 고정된 예시를 사용했다.

| 검증한 행동 | 기대 결과 |
| --- | --- |
| 빈 장바구니 | 0개, 0원, 0종류 |
| 사과 2개와 우유 1개 담기 | 3개, 5,500원, 2종류 |
| 사과 3개에서 차례로 빼기 | 2개 → 1개 → 상품 제거 |
| 없는 품목 빼기·삭제 | 상태가 그대로이고 음수 수량이 생기지 않음 |
| 같은 상품 반복해서 담기 | 최대 9개 |
| 등록되지 않은 ID 사용 | 동작과 합계에서 제외 |
| 한 품목 모두 삭제 | 나머지 상품은 유지 |
| 전체 비우기 | 빈 장바구니 |
| 동결한 이전 상태로 각 동작 수행 | 이전 객체는 변경되지 않음 |

별도 테스트 프레임워크를 추가하지 않고 Node의 `node:test`와 `node:assert/strict`를 사용했다. 다음 명령은 `apps/mobile` 폴더에서 실제 실행했고 **9개 모두 통과**했다.

```bash
node --experimental-strip-types --test src/features/cart/cart.test.ts
```

Node의 타입 제거 실행은 TypeScript의 타입 표기를 지우고 코드를 실행하는 방식이다. 타입이 올바른지 검사하지는 않으므로 TypeScript 검사를 따로 진행한다. [Node의 TypeScript 지원](https://nodejs.org/api/typescript.html)

## 개발 중 만난 문제

첫 전체 타입 검사에서 `node:test`·`node:assert/strict` 타입과 `./cart.ts` import에 오류가 났다. 테스트 실행 자체는 성공했지만, 프로젝트의 TypeScript 설정에는 Node 타입과 `.ts` 확장자 import 허용이 명시되어 있지 않았다.

테스트가 다른 패키지에 우연히 따라온 Node 타입에 의존하지 않도록 `@types/node` 26.6.6을 개발 의존성에 명시했다. 실제 설치 명령은 다음과 같았다.

```powershell
npx.cmd expo install --dev @types/node@^26.6.6
```

`tsconfig.json`에는 `types: ["node"]`와 `allowImportingTsExtensions: true`를 적용했다. Expo 기본 설정의 `noEmit: true`는 유지했다. 이후 앱 전체 타입 검사도 통과했다.

수정 전에도 두 파일 자체의 타입은 필요한 옵션을 명시한 다음 명령으로 확인했다. TypeScript 6에서는 파일명을 직접 지정할 때 `--ignoreConfig`도 필요했다.

```bash
node node_modules/typescript/bin/tsc --ignoreConfig --noEmit --strict --target esnext --module preserve --moduleResolution bundler --skipLibCheck --esModuleInterop --allowImportingTsExtensions --types node src/features/cart/cart.ts src/features/cart/cart.test.ts
node node_modules/eslint/bin/eslint.js src/features/cart/cart.ts src/features/cart/cart.test.ts
```

두 명령은 통과했다. Node 테스트 실행 중 `MODULE_TYPELESS_PACKAGE_JSON` 경고도 보였다. 모듈 형식을 자동 판별했다는 경고이며 테스트 실패는 아니었다. 경고를 없애려고 앱 전체의 모듈 형식을 변경하지는 않았다.

## 갤럭시 실기기 확인 기록

2026-11-11에 사용자가 개발 서버를 다시 켜고 갤럭시 Expo Go에서 사과 2개와 우유 1개를 담았다. 화면에 총 3개·5,500원이 정상 표시된다고 보고했다. 이 결과로 상품 담기와 합계 표시를 실기기에서 확인했다. 이어서 사과를 한 개씩 두 번 빼고 남은 우유도 빼는 세 단계가 모두 정상 동작했다고 보고했다. 마지막에는 0개·0원과 장바구니가 비었다는 안내가 표시되었다.

사용자가 확인한 감소 과정의 합계는 차례로 2개·4,000원, 1개·2,500원, 0개·0원이다.

같은 날 사용자가 사과 9개·13,500원과 9개까지 담을 수 있다는 안내를 확인했다. + 버튼이 흐려지고 더 눌러도 수량이 늘어나지 않았으며, 사과 9개를 담은 상태로 두었다고 보고했다. 이로써 수량 상한과 상한 도달 시 버튼 동작을 실기기에서 확인했다.

이어서 사용자는 내 장바구니의 사과 옆 빼기 버튼을 누르자 사과 9개가 모두 빠지고 우유만 1개·2,500원으로 남았다고 보고했다. 이로써 품목 전체 삭제가 선택한 상품에만 적용되는 것을 실기기에서 확인했다. 우유 1개는 다음 확인을 위해 그대로 두었다.

같은 날 사용자는 장바구니 비우기를 누른 뒤 0개·0원과 장바구니가 비었다는 안내가 표시되고, 우유와 당근 카드에 담기 버튼이 다시 보인다고 보고했다. 이로써 여러 품목을 한 번에 비우고 상품 카드의 조작 상태가 함께 갱신되는 것을 실기기에서 확인했다.

마지막으로 사과를 담고 PC의 Expo 개발 서버 터미널에서 r을 눌러 새로고침하도록 안내했다. 사용자는 새로고침 후 0개·0원과 장바구니가 비었다는 안내가 나오고, 사과에 다시 담기 버튼이 표시된다고 보고했다. 장바구니를 메모리에만 보관하는 현재 단계에서 이 초기화는 의도한 동작이다.

이로써 이번 장의 갤럭시 기본 동작 확인을 마쳤다. iPhone 실기기·글자 확대·화면 읽기 기능 등 출시 전 사용성 검증은 별도로 남아 있다. 다음 작업은 사용자가 변경 내용을 검토하고 장바구니 구현과 검증 기록을 직접 커밋하는 것이다.

## Git Bash에서 직접 확인할 순서

프로젝트 루트에서 연 Git Bash를 기준으로 한다. 의존성 설치가 필요한 새 환경이라면 아래의 `cd apps/mobile` 다음에 `npm ci`를 실행한다.

```bash
cd apps/mobile
npm test
npm start
```

`npm test`는 위 Node 테스트 명령을 실행하도록 연결했다. 휴대전화용 개발 서버가 이미 실행 중이라면 새 서버를 시작하지 않고 기존 터미널의 QR을 사용한다. 갤럭시 확인은 아래 순서로 직접 진행한다.

갤럭시 Expo Go에서 현재 개발 서버의 QR을 열고 다음을 차례로 확인한다.

1. 사과를 2개, 우유를 1개 담아 하단에 3개·5,500원이 표시되는지 본다.
2. 상품 목록 아래로 내려가 장바구니의 품목별 수량과 금액을 본다.
3. 사과를 하나씩 빼서 마지막 하나를 뺐을 때 해당 품목이 사라지는지 확인한다.
4. 같은 상품을 9개까지 담고 더 담을 수 없는지 확인한다.
5. 품목 전체 삭제와 장바구니 비우기를 확인한다.
6. 새로고침하면 장바구니가 비워지는지 확인한다.

화면 확인이 끝난 뒤 사용자가 변경 내용을 검토하고 직접 커밋·업로드한다. 이번 작업에서는 스테이징·커밋·태그·push를 수행하지 않았다. 다음 개발 단계는 놀이돈을 정하고 거스름돈을 계산하는 기능이다.
