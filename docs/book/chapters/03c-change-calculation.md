# 03장 보충. 받을 거스름돈 계산하기

날짜: 2026-11-12

시작 기준: `8309377` — 놀이돈 선택과 갤럭시 자동 검사·기록 구현. 사용자가 이 커밋을 GitHub에 업로드했다고 확인한 뒤 이번 단계를 시작했다.

## 목표와 화면

낼 놀이돈을 충분히 고르면 “받을 거스름돈”과 계산식을 보여 준다. 계산 기준은 **낼 돈 − 물건값**이다. 거스름돈은 현재 선택에서 파생되는 값이며 별도의 상태로 저장하지 않는다.

| 물건값 | 낼 돈 | 거스름돈 | 예산 10,000원에서 남을 돈 |
| --- | --- | --- | --- |
| 5,500원 | 10,000원 | 4,500원 | 4,500원 |
| 1,000원 | 5,000원 | 4,000원 | 9,000원 |
| 1,000원 | 1,000원 | 0원 | 9,000원 |
| 10,000원 | 10,000원 | 0원 | 0원 |
| 5,500원 | 5,000원 | 계산하지 않음, 500원 부족 안내 | 4,500원 |

두 번째 예시는 예산 잔액을 거스름돈으로 잘못 표시하는 오류를 발견하기 위한 핵심 사례다. 예산과 낼 돈이 모두 10,000원이면 두 계산의 결과가 같아 그 오류를 놓칠 수 있다.

충분한 돈을 고르면 기존 선택 안내 아래에 거스름돈 카드가 나타난다. 카드에는 큰 금액, “낼 돈 − 물건값”, 숫자 계산식과 짧은 설명을 표시한다. 딱 맞게 고르면 0원을 숨기지 않고 안내한다. 미선택·부족·예산 초과·빈 장바구니에서는 거스름돈 카드를 표시하지 않는다.

이 단계는 선택한 돈으로 받게 될 금액을 계산해 보는 기능이다. 결제 완료로 처리하거나 예산을 차감하지 않으며, 아이가 답을 입력하는 거스름돈 퀴즈는 후속 단계다.

## 핵심 코드와 이유

- `payment.ts`: `getPaymentSummary`가 `changeAmountKrw`를 함께 반환한다. 충분한 돈을 선택한 `ready`에서만 선택 금액에서 물건값을 뺀다.
- `null`은 계산할 수 없는 상태이고, `0`은 딱 맞게 낸 유효한 결과다. 값이 참인지 검사하는 방식으로는 0원을 놓치므로 화면에서도 `!== null`로 구분한다.
- 기존 쇼핑 reducer를 그대로 사용한다. 상품 변경·선택 취소 시 선택 금액이 초기화되므로 거스름돈도 같은 렌더링에서 사라진다.
- `payment-selector.tsx`: 금액과 계산식을 함께 묶은 접근성 라벨을 제공한다. 핵심 처리 이유는 한국어 주석으로 남겼다.

새 패키지나 DB 테이블은 추가하지 않았다. Expo SDK 58 문서와 React Native Text·접근성 문서를 확인한 뒤 기존 컴포넌트와 스타일을 확장했다.

## 자동 검증

먼저 결제 계산 테스트를 실행해 **17개 모두 통과**했다. 기존 15개 테스트에 거스름돈 결과 검증을 보강하고, 예산 잔액과 거스름돈의 차이 및 충분한 금액에서 부족한 금액으로 바꿀 때 이전 결과 제거를 검사하는 테스트를 추가했다.

실행한 명령:

```bash
cd apps/mobile
node --experimental-strip-types --test src/features/payment/payment.test.ts
```

단위 검사에서는 4,500원·4,000원·0원, 빈 장바구니·미선택·부족·예산 초과, 상품 변경·선택 취소·비우기 이후 결과를 확인한다. Node의 기존 MODULE_TYPELESS_PACKAGE_JSON 경고는 발생했으나 테스트는 통과했다.

Maestro 흐름에는 위 계산 사례, 0원 표시, 이전 거스름돈 제거, 예산 잔액 유지, 재실행 초기화를 추가한다. 화면에서 실제 계산식까지 확인하며 기존 장바구니·예산·금액 선택 검사도 유지한다. 원본 화면 캡처는 Git에서 제외한 .artifacts 폴더에 저장한다.

전체 검사와 자동 커밋은 다음 명령으로 진행한다.

```bash
npm run verify:device -- --message "feat: 거스름돈 계산과 실기기 자동 검증 추가"
```

실행기는 전체 앱 테스트, 커밋 보호 테스트, 타입·ESLint·세 플랫폼 번들 및 갤럭시 검사를 순서대로 실행한다. 성공한 경우에만 [최종 실기기 검증 기록](../verification/latest-android.md)을 작성하고 같은 소스와 원고를 커밋한다. 검사 전에는 실기기 성공으로 기록하지 않는다. 해당 커밋의 검증 문서에서 실제 실행 ID·시각·기기·결과를 확인할 수 있다.

이 원고와 코드를 함께 추가한 커밋은 다음 명령으로 확인한다.

```bash
git log -1 --format="%h %s" -- docs/book/chapters/03c-change-calculation.md
```

iPhone 실기기·TalkBack 음성 읽기·스토어 배포 빌드는 이번 검증 범위에 포함하지 않는다.
