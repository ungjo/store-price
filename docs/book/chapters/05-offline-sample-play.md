# 05장. 기다리지 않고 예시 상품으로 놀이하기

날짜: 2026-11-13

시작 커밋은 `f6f4ccb`다. 앞 단계에서는 실제 가격의 비공개 기록을 USB로 연결한 갤럭시에서 읽는 개발용 미리보기를 구현했다. 이번에는 앱이 원격 상품 목록을 읽는 동안에도 내장 예시로 바로 놀이를 시작하는 흐름을 구현한다.

사용자는 이 개선을 다음 단계로 선택했고, 실제 갤럭시 검사를 위해 USB 디버깅을 다시 허용했다.

## 기다림 화면에서도 선택할 수 있게 하기

기존 앱에는 설정 없음·빈 목록·연결 실패 때 예시 상품을 선택하는 기능이 있었다. 하지만 원격 조회가 진행 중이면 사용자는 응답이나 오류를 기다려야 했다. 조회 제한 시간은 응답 본문 읽기까지 포함해 12초다. 연결이 느릴 때 이 대기 시간이 아이의 놀이 시작을 늦춘다.

이번 변경은 **가게 물건을 가져오고 있어요** 화면에 **예시 상품으로 바로 놀이하기** 버튼을 제공한다. 안내는 **기다리지 않고 예시 상품으로 놀이할 수도 있어요.**로 표시한다. 사용자가 직접 고르면 앱에 포함된 예시 6개로 시작하며, 자동으로 원격 목록을 예시 목록으로 바꾸지는 않는다.

예시 놀이에는 **앱에 준비된 예시 상품으로 놀고 있어요.**라는 출처 안내가 나온다. 실제 이마트 판매 가격을 새로 받았다는 의미가 아니다. 내장 예시의 장바구니·놀이돈·거스름돈·영수증은 기존 계산 규칙을 사용한다.

## 취소와 늦은 응답을 함께 다루기

사용자가 예시를 선택하면 진행 중인 목록 요청을 취소한다. 취소 요청만으로 상태 보존을 보장하지는 않는다. 이미 응답이 끝나가거나 통신 구현이 취소를 즉시 반영하지 않는 경우에도 이전 요청이 예시 목록을 다시 덮어쓰지 않아야 한다.

목록 요청의 시작·재시도·예시 선택·화면 해제를 한 흐름에서 관리한다. 현재 요청에 속한 결과만 반영하고, 취소한 요청의 늦은 성공·실패는 무시한다. 예시를 선택한 뒤 새 상품 목록으로 화면을 다시 만들거나 장바구니를 초기화하지 않도록 한다.

`catalog-session.ts`에서는 요청 번호를 먼저 바꾼 뒤 이전 통신을 취소한다. 결과를 반영하기 전에 현재 화면 연결, 선택한 출처, 요청 번호와 취소 상태를 함께 확인한다. 개발 모드에서 화면 연결과 정리가 반복되는 경우에는 이전 정리 함수가 새 요청을 취소하지 않도록 화면 연결 번호도 구분한다.

| 파일 | 역할 |
| --- | --- |
| apps/mobile/src/components/catalog-loader.tsx | 목록 안내와 즉시 예시 선택 버튼, 현재 상태에 맞는 화면 연결 |
| apps/mobile/src/features/catalog/catalog-session.ts | 요청 시작·취소·재시도·예시 선택과 늦은 응답 차단 |
| apps/mobile/src/features/catalog/catalog-session.test.ts | 실제로 늦게 완료하는 요청으로 선택·취소·재시도·정리 순서 검사 |
| apps/mobile/src/features/catalog/catalog-device-fixture.ts | 개발 검사에서만 조회를 지연하고 취소 뒤 늦게 완료하는 상황 재현 |
| apps/mobile/.maestro/catalog-loading-choice.yaml | 대기 중 예시 선택·놀이·영수증·다시 장보기의 실기기 흐름 |
| apps/mobile/App.tsx | 준비된 목록으로 기존 시장놀이 화면 시작 |

예시 영수증의 **다시 장보기**는 같은 예시 상품으로 새 놀이를 시작한다. 원격 목록으로 시작했던 놀이의 **다시 장보기**는 기존처럼 원격 목록을 다시 읽는다. 이번 단계는 DB·가격 자료·개발용 실제 가격 미리보기의 공개 조건을 변경하지 않는다.

원격 목록이 아주 빨리 도착하면 대기 화면이 중간에 그려지지 않을 수 있다. 새 놀이가 대기 화면의 표시 여부에 의존하지 않도록 다시 불러올 때 놀이 회차를 올리고, 그 회차를 화면의 `key`로 사용했다. 새 회차에는 이전 영수증과 장바구니가 남지 않는다. 검사 진행 표시가 갱신되는 것만으로는 회차를 바꾸지 않아 진행 중인 예시 놀이를 유지한다.

## 연결 없이 할 수 있는 범위

내장 예시는 앱 코드에 함께 들어 있으므로 목록을 받기 위해 DB 연결을 기다릴 필요가 없다. 이번 개선에서 확인할 대상은 이미 실행된 앱의 예시 선택과 이후 놀이 상태다.

Expo Go가 처음 앱 코드를 받아오는 과정과 설치형 앱을 인터넷 없이 처음 실행하는 동작은 별도다. 이 단계의 검사만으로 오프라인 첫 실행을 보장한다고 기록하지 않는다. 마지막 원격 목록을 디스크에 보관하는 영구 캐시, 새 패키지, 기기 네트워크 설정 변경도 추가하지 않는다.

## 실기기 검사에서 대기 상태 재현하기

실제 서버가 빨리 응답하면 대기 화면이 짧게 지나가 버튼을 검사하기 어렵다. 그래서 전체 자동 검사의 첫 단계에서 개발용 지연 요청을 사용한다. 개발 모드, 올바른 검사 실행 번호, `pending-choice` 설정이 함께 있어야 켜지며 일반 실행에는 적용하지 않는다.

이 요청은 사용자가 예시를 선택해 취소한 뒤에도 의도적으로 늦게 성공시킨다. 검사는 취소 뒤 응답이 끝났다는 표시와 예시 출처·상품 6개를 함께 확인한다. 예시 사과를 담고 10,000원을 골라 거스름돈 8,500원을 맞힌 뒤 영수증과 다시 장보기까지 확인하도록 구성한다. 다시 장보기 후 새 조회가 생기지 않는지도 확인한다.

이 단계에는 별도 실행 번호의 `-loading` 접미사를 붙이고 `loading-result.xml`과 `maestro-loading` 폴더에 결과를 남긴다. 이어서 실행기가 직접 시작한 8091 서버를 종료하고 지연 요청 설정을 뺀 서버로 다시 실행한다. 실제 Supabase 공개 목록을 읽는 기존 전체 회귀 검사와 원격 HTTP 확인을 별도로 진행한다. 두 실기기 단계의 JUnit 결과가 모두 통과해야 기록과 커밋을 허용한다.

휴대전화의 Wi-Fi나 모바일 데이터 설정을 바꾸지 않는다. 이 검사는 늦은 요청에 대한 앱 동작을 확인하며 인터넷을 실제로 끊은 검사나 오프라인 첫 실행 검사를 대신하지 않는다. 영수증만 확인하는 부분 검사에는 새 단계를 실행하지 않으며, 부분 검사로 전체 검증 커밋을 만들지 않는다.

## 준비와 검증 상태

개발을 재개할 때 로컬 시작 커밋을 확인했다. 처음에는 갤럭시의 USB 디버깅 승인이 필요해 화면 검사에 들어가지 못했다. 이후 사용자가 승인을 완료했고 2026-11-13 KST에 `device` 연결 상태와 잠금 해제를 확인했다. 초기 점검 실패와 승인 후 전체 검사는 구분해서 기록한다.

이번 단계에서 확인할 내용은 다음과 같다.

1. 목록을 읽는 중에 예시 선택 버튼이 표시되고 선택 즉시 예시 6개로 이동하는지.
2. 진행 중인 요청을 취소하고, 늦은 성공·실패가 예시 출처와 놀이 상태를 덮어쓰지 않는지.
3. 원격 읽기·재시도·설정 없음·빈 목록·오류 처리의 기존 동작이 유지되는지.
4. 예시로 시작한 장바구니·돈 선택·문제·영수증과 다시 장보기가 동작하는지.
5. 일반 원격 Supabase 흐름과 전체 갤럭시 회귀 검사도 통과하는지.

별도 코드 검사에서 목록 상태 검사 12개와 개발용 지연 요청 검사 6개, 합계 18개가 통과했다. 타입·ESLint 검사도 통과했다. ESLint의 첫 실행은 로컬 검사 캐시 파일 쓰기 권한 때문에 중단됐고, 필요한 실행 권한을 적용한 재실행에서 통과했다. 공개 카탈로그·미리보기 서버 검사 도구 19개, Maestro YAML 5개의 문법 검사와 자동 실행기 JavaScript 문법 검사도 통과했다. 이 결과는 갤럭시를 실제로 조작한 검사와 구분한다.

전체 코드 검사에서는 기존 107개와 새 18개를 합친 앱 검사 125개, DB 검사 63개, 커밋 보호 검사 9개가 통과했다. 타입·ESLint·Android·iOS·웹 번들과 실제 Supabase 공개 REST의 예시 6개, 비공개 스키마·승인 메모 접근 차단도 확인했다. 이 실행의 원본은 Git에서 제외된 `.artifacts/device/20261112T161932249Z-sample-code/`에 남겼다.

그 뒤 빠른 원격 응답에서도 새 놀이 회차로 화면을 초기화하는 `Fragment key` 처리를 보완했다. 최종 앱 코드로 다시 실행한 검사 125개와 타입·ESLint·세 플랫폼 번들이 모두 통과했다. 재검사 원본은 `.artifacts/device/20261112T162114886Z-sample-final-code/`에 남겼다. 새 검사 18개가 전체 125개에 포함되므로 두 수를 더하지 않는다.

사용한 코드 검사 명령은 다음과 같다. 저장소 루트에서 시작하며 사용자 실행 표기는 Git Bash 기준이다.

```bash
node --test scripts/device/git-guard.test.mjs
node --experimental-strip-types --test scripts/device/catalog-http-check.test.mjs
node --test scripts/device/private-price-preview.test.mjs
npm --prefix scripts/database test
cd apps/mobile
npm test
npm run typecheck
npm run lint
npm run export:check
```

연결 점검 실행 `20261112T162141292Z-51f150ea`는 갤럭시가 `unauthorized` 상태여서 종료 코드 1로 멈췄다. Java·ADB·Maestro 도구를 확인했지만 실제 화면은 조작하지 않았고, 화면 유지나 네트워크 설정도 바꾸지 않았다. 이 실패 실행 요약의 커밋 값은 `null`이다. 그 뒤 사용자가 휴대전화에서 USB 디버깅을 허용해 연결 조건을 해결했다.

예시 선택 단계는 기존 전체 명령에 포함되므로 이를 켜는 별도 명령줄 옵션은 필요 없다. 이번 실행은 기존 비공개 실제 가격 미리보기의 회귀 검사도 함께 수행한다. 모바일 앱 폴더의 Git Bash에서 다음 명령을 사용하며, 비공개 자료 경로는 저장소 루트를 기준으로 해석한다.

```bash
npm run verify:device -- --private-price-preview .artifacts/catalog/private-preview.json --message "feat: 기다리지 않고 예시 상품으로 놀이 시작"
```

전체 실행 `20261112T163607752Z-34ce65ac`은 앱 125개·DB 63개를 포함한 코드 검사를 통과했지만, 예시 선택 단계에서 11개 명령을 완료한 뒤 `catalog-test-late-marker`를 찾지 못해 실패했다. 실패 화면에서는 내장 예시 6개와 출처가 정상 표시됐고, 늦은 응답·요청 수를 알려 주는 검사 표시가 Android 하단 시스템 탐색 영역에 가려져 있었다. 이 실행은 커밋하지 않았으며 임시 화면 유지 설정도 원래 값 `0`으로 복구했다.

개발 검사 화면의 바깥을 `SafeAreaProvider`와 하단 `SafeAreaView`로 감싸 실제 기기의 시스템 영역만큼 여백을 확보했다. 고정 24px 여백에 의존하지 않도록 검사 표시 자체의 하단 여백은 8px로 조정했다. 일반 놀이 화면에는 이 검사 전용 배치를 적용하지 않는다. 수정 후 타입·ESLint 검사가 통과했으며, 전체 실기기 검사를 다시 실행한다.

연결 확인과 코드 검사 성공만으로 전체 실기기 성공을 판정하지 않는다. 최종 결과는 이 변경과 함께 남기는 [Android 검증 기록](../verification/latest-android.md)에서 검사 시작 HEAD가 `f6f4ccb`인지와 예시 선택·기존 전체 놀이의 실제 결과를 함께 확인한다. 앞 커밋에 포함된 이전 성공 기록을 이번 기능의 실기기 근거로 사용하지 않는다.

모든 코드·실기기 검사와 파일 지문 검사가 통과할 때만 확인한 변경과 개발 기록을 로컬 커밋한다. 휴대전화가 연결되지 않거나 검사가 실패하면 커밋하지 않는다. GitHub 업로드는 별도 요청에 따라 진행한다.
