# 04장 보충. 실제 가격을 개발용 앱에서 미리보기

날짜: 2026-11-12

시작 커밋은 `0184ef9`다. 앞 단계에서 실제 상품 3개의 가격·출처·규격·관측 시각을 비공개 DB에 저장하고 자동 검사를 통과했다. 사용자가 GitHub 업로드를 확인한 뒤 실제 가격을 앱에서 표시하는 다음 단계를 요청했다. 표시 범위를 확인하는 질문에서 **본인 갤럭시의 개발용 미리보기부터 진행**을 선택했다.

이번 단계는 비공개 기록을 개발 중인 휴대전화에서 읽는 기능이다. 일반 사용자용 카탈로그는 예시 6개를 유지한다. 실제 자료를 공개 승인 상태로 바꾸거나, 품절 자료를 판매 가능한 상품처럼 장바구니에 넣는 기능은 포함하지 않는다.

## 두 가지 시각을 구분하기

미리보기 자료는 Supabase 연결 도구로 DB를 새로 조회해 만든다. 앞 단계에서 저장했던 입력 파일을 지금 DB에서 읽은 결과처럼 사용하지 않는다. 대상 프로젝트와 상품·관측의 연결, 비활성·비공개 상태를 확인한 뒤 화면에 필요한 필드만 전달한다.

2026-11-12 19:56:24 KST에 실제 Supabase 조회 결과 3행을 `.artifacts/catalog/private-preview.json`에 기록했다. DB 조회 시각은 `2026-11-12T10:56:24.568Z`이며, 상품 페이지의 관측 시각은 앞 단계의 같은 날 19:22 KST를 유지한다. 이 단계에서 DB의 상품·가격·권한·공개 상태를 수정하거나 상품 페이지를 새로 관측하지 않았다.

가격의 `observed_at`은 상품 상세 화면에서 금액을 확인했던 시각이다. 미리보기 자료를 DB에서 가져온 시각은 별도로 기록한다. DB를 지금 읽었다고 오래된 관측 시각을 현재 시각으로 바꾸지 않는다. 화면은 **확인 당시 가격**이라고 설명하고 규격·출처·확인 시각·재고 상태를 함께 표시한다.

재고 미확인과 품절은 서로 다르다. 로그인·배송지를 설정하지 않은 관측에서는 배송지별 판매 가능 여부를 추측하지 않는다. 내부 자료 기한이 지나면 오래된 관측이라는 사실을 알려 주며, 이 기한은 판매자가 보장한 가격 유효기간이 아니다.

## 실제 자료를 앱 소스 밖에 두기

실제 상품 자료는 Git에서 제외된 `.artifacts/catalog/private-preview.json`에 보관한다. 모바일 코드에서 이 JSON을 import하지 않고, 관리자 키·승인 메모도 앱에 넣지 않는다. 따라서 저장소를 복제하거나 배포 번들을 만든다고 실제 자료가 자동으로 포함되지 않도록 구성한다.

개발 중에는 컴퓨터의 `127.0.0.1:8092`에만 연결을 받는 작은 서버가 필요한 자료를 제공한다. 실행마다 새 임시 토큰을 만들고, USB로 연결한 갤럭시가 이 서버를 읽게 한다. 일반 네트워크 주소에 가격 서버를 열지 않는다. 서버는 읽기 요청과 정해진 주소·인증 조건만 허용하고 응답을 캐시하지 않도록 한다.

미리보기를 시작할 때 사용하는 DB 조회 자료에는 24시간 이내라는 기한을 둔다. 자료를 새로 준비할 때에도 가격의 원래 관측 시각은 바꾸지 않는다. 실행 중 DB나 SSG.COM을 계속 조회하는 자동 갱신 기능은 아니다.

앱은 개발 환경과 명시적인 미리보기 설정이 함께 있을 때만 이 기능을 표시한다. 임시 토큰은 이 로컬 미리보기의 접근 값이며 Supabase 관리자 키가 아니다. 일반 코드 검사·배포 export에서는 미리보기 설정을 제거한다. 배포 결과에 실제 상품 식별자·이름·미리보기 토큰이 없는지도 별도로 검사한다.

## 놀이 상태를 유지하는 읽기 전용 창

미리보기는 기존 놀이 화면 위에 열리는 별도의 창이다. 상품명·규격·원 단위 가격·출처·확인 시각·재고 상태를 읽을 수 있다. 카드에는 장바구니 버튼이나 상품 사진을 넣지 않는다.

화면의 진입 버튼은 **실제 가격 미리보기 · 개발용**, 창 제목은 **확인 당시 가격**이다. 출처는 **SSG.COM 이마트 온라인**으로 표시하고, 확인 시각은 한국 시간으로 읽을 수 있게 한다. 재고 미확인·확인 당시 품절·확인 당시 판매 가능을 구분한다. 화면 위에는 DB 조회 시각을 따로 표시해 가격 관측과 혼동하지 않도록 한다.

열 때마다 준비된 미리보기 자료를 요청하고, 닫기 버튼이나 Android 뒤로가기로 나가면 요청과 화면 자료를 정리한다. 이전 요청이 늦게 끝나도 닫은 화면에 결과를 다시 넣지 않도록 한다. 빈 자료·연결 실패·잘못된 응답은 각각 안내하며 예시 데이터를 실제 가격이라고 대신 표시하지 않는다.

**PC 기록 다시 불러오기**는 PC 서버의 자료를 다시 읽는 동작이다. 상품 페이지를 새로 관측하거나 DB 자료를 자동 갱신하지 않는다. 내부 기한을 넘긴 관측에는 **내부 재확인 기한이 지난 기록이에요.**라고 표시하며, 기한 전에도 확인 당시 가격과 현재 가격이 다를 수 있음을 알린다.

기존 장바구니·낼 돈·퀴즈·영수증 상태와 미리보기 상태는 분리한다. 창을 열고 닫아도 놀이 상태가 바뀌지 않는지 실제 기기에서 확인한다. 새로운 앱 경로로 이동하는 화면은 아니므로 이번 단계에서 별도 탐색 구조를 도입하지 않는다.

주요 파일은 다음 역할로 나눈다.

| 파일 | 역할 |
| --- | --- |
| apps/mobile/src/features/catalog/real-price-preview.ts | 미리보기 설정·응답 검증, 읽기·취소, 시각·재고 표시 |
| apps/mobile/src/components/real-price-preview.tsx | 개발 설정에서만 열리는 읽기 전용 창과 상태 안내 |
| apps/mobile/App.tsx | 기존 놀이 화면에 개발용 미리보기 연결 |
| scripts/device/private-price-preview.mjs | 비공개 DB 조회 자료 검증·서버·자료 지문·배포 결과 검사 |
| scripts/device/start-price-preview.mjs | 사용자가 다시 확인할 전용 서버·USB 연결 실행 |
| scripts/device/verify.mjs | 코드 검사·기기 검사·기록·커밋에 미리보기 검증 연결 |

가격 표시와 통신의 핵심 로직에는 검증이 필요한 이유와 놀이 상태를 보존하는 이유를 한국어 주석으로 설명한다.

## 실행과 정리

갤럭시를 USB로 연결하고 USB 디버깅을 허용한 뒤 잠금을 해제한다. DB에서 읽은 미리보기 자료가 준비된 작업 폴더에서 다음 명령을 사용한다. 사용자 명령은 Git Bash 기준이다.

```bash
cd apps/mobile
npm run start:price-preview
```

실행기는 추가 인자를 받지 않으며 저장소 루트의 `.artifacts/catalog/private-preview.json`을 사용한다. 가격 서버는 8092, 전용 Expo 서버는 8093 포트를 쓰고 연결한 갤럭시의 Expo Go를 연다. 기존 일반 서버의 8082 포트는 변경하지 않는다. 5초마다 자료·설정 지문을 확인해 실행 중 바뀌면 종료하므로, 자료를 새로 준비한 뒤에는 실행기도 다시 시작한다.

화면 확인을 마치면 해당 터미널에서 Ctrl+C로 종료한다. 이번 실행이 만든 서버와 USB 연결만 정리하며, 사용자가 미리 만든 연결을 덮어쓰거나 제거하지 않는다. 실행 중 사용자가 USB 포트 연결을 바꾼 경우에도 바뀐 연결을 제거하지 않는다.

자동 검사도 전용 서버를 사용하지만 검사 후 정리한다. 검사를 마친 뒤 사용자가 직접 살펴보려면 위 실행기를 다시 시작한다. 이 기능은 PC와 USB 연결이 필요한 개발 도구이며 일반 사용자용 앱 배포를 뜻하지 않는다.

## 검증 범위와 기록

이번 단계는 다음 근거를 구분해서 남긴다.

1. **원격 조회:** 실제 DB에서 읽은 대상 프로젝트·상품 수·관측 상태와 자료 지문.
2. **입력·통신 검사:** 잘못된 금액·시각·출처·응답, 취소·제한 시간·인증·서버 요청 제한.
3. **배포 검사:** 미리보기 비활성 설정과 실제 자료·임시 토큰의 번들 포함 여부.
4. **실기기 검사:** 미리보기 내용, 닫기·뒤로가기, 기존 놀이 상태 유지와 전체 회귀 흐름.
5. **커밋 보호:** 검사 전후 소스·설정·미리보기 파일의 지문이 같은지 확인.

미리보기 JSON은 Git에서 제외되므로 기존 소스 파일 지문만으로는 검사 중 자료 변경을 감지할 수 없다. 자동 실행기는 이 파일의 지문과 실제 응답을 별도로 확인한다. 기기의 기대 값도 실행 중 만드는 비공개 검사 자료로 전달하고, 실제 상품 값은 검사 YAML이나 책 원고에 적지 않는다.

실제 원격 DB 조회와 비공개 자료 파일 생성 결과를 확인했다. 미리보기 모듈 검사 14개와 타입·ESLint 검사가 통과했다. 미리보기 서버 검사 9개와 기존 공개 카탈로그 검사 도구 10개도 통과했다. Maestro 미리보기 흐름의 문법도 확인했다.

전체 회귀 검사 전 갤럭시에서 실행기를 직접 확인했다. 8093의 Expo Go가 열리고 실제 DB 기록 3개를 읽는 데 성공했다. 화면 캡처에서 상품 규격과 가격, 관측 시각 19:22 KST와 DB 조회 시각 19:56 KST의 분리 표시를 확인했다. 실제 상품명·가격·상세 주소가 들어 있는 화면 자료는 공개 원고에 싣지 않는다.

연결 실패 흐름의 기기 검사 10개 명령도 완료했다. 실행기를 종료한 뒤 8092·8093 서버는 닫히고 기존 8082 서버는 유지되는 것을 확인했다. 미리보기의 다시 불러오기는 오류 안내로 바뀌며 이전 가격을 그대로 남기지 않았다. 다시 시도해도 오류를 표시했고, 닫기를 누르면 원래 화면의 미리보기 버튼으로 돌아왔다.

이 확인은 미리보기 실행·연결 실패에 대한 실기기 근거이며 전체 시장놀이 회귀 검사와는 구분한다. 전체 갤럭시 검사 성공은 같은 커밋에 포함되는 [Android 검증 기록](../verification/latest-android.md)의 실행 기준 HEAD와 각 단계 결과로 확인한다. 이전 `0184ef9`의 성공을 이번 화면 기능의 성공으로 대신하지 않는다.

전체 자동 검사와 조건부 로컬 커밋은 모바일 앱 폴더에서 다음 명령으로 실행한다. `--private-price-preview`의 경로는 저장소 루트를 기준으로 해석한다.

```bash
npm run verify:device -- --private-price-preview .artifacts/catalog/private-preview.json --message "feat: 실제 가격 개발용 미리보기 추가"
```

첫 전체 실행 `20261112T111106056Z-fa0cab76`에서는 앱 단위 검사 107개, DB 검사 63개, 커밋 보호 검사 9개, 공개 카탈로그 검사 도구 10개, 미리보기 서버 검사 9개와 타입·ESLint·세 플랫폼 번들 검사가 통과했다. 실제 공개 REST 조회도 통과했다. 그러나 기기 검사에서 14개 명령을 완료한 뒤 새 미리보기 흐름이 예시 사과의 담기 버튼을 찾지 못해 실패했다.

실패 화면을 보니 처음 화면의 아래쪽에 상품이 있는데 검사 흐름은 위쪽으로 찾고 있었다. `.maestro/real-price-preview.yaml`의 첫 탐색을 `DOWN`으로 바꾸고, 정확한 `product-sample-apple-add` 식별자로 찾도록 수정했다. 이 실행은 전체 통과가 아니므로 커밋하지 않았으며, 검사 중 임시로 켠 화면 유지 설정도 원래 값 `0`으로 복구했다. 수정 뒤 전체 검사를 다시 실행하며, 최종 결과는 위 검증 기록으로 확인한다.

모든 코드·실기기 검사가 통과하고 검사 중 파일이 바뀌지 않았을 때만 로컬 커밋한다. GitHub 업로드와 태그 생성은 별도 사용자 요청 후 진행한다.
