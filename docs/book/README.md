앞·뒤 표지를 제외한 **7부 20장, 부록 A~D, 408쪽**의 개발 실습서다. Windows에서 작업 폴더를 열고 첫 코드를 쓰는 데서 시작해, 독자의 Android 기기에 설치한 APK로 장을 보고 영수증을 확인하는 데서 마친다. PDF 목차의 각 장·절 제목을 누르면 해당 쪽으로 이동한다. 브라우저판 위쪽에는 읽고 있는 본문 쪽이 표시된다. 쪽 번호를 입력하고 **이동**을 누르면 종이책의 같은 위치가 열린다.

2장(20쪽)에서 도구를 설치하고, 2.6절(44쪽)에서 자료실의 예제 ZIP을 받아 VS Code로 연다. 46쪽에서 압축을 푼 폴더와 책에서 쓰는 이름인 `kit`을 확인한다. 47쪽에서 `steps`의 11·13·14가 보조 실험을 가리키는 이유를 읽는다. 그림 2-22~2-24(47~49쪽)에서 압축을 푼 폴더를 연 VS Code 화면, **터미널 → 새 터미널**, `node start.mjs 20`으로 생긴 폴더를 차례로 확인한다. 49~52쪽에서 20장 앱 폴더로 이동해 브라우저에서 상품 12개를 확인한다. 53쪽부터 장별 참고본을 차례로 여는 방법이 나온다.

54~56쪽에서는 VS Code에서 **F1 → 작업: 작업 실행 → 실습 명령어 도움말**을 선택한다. 그림 2-29(54쪽)는 작업을 고르는 목록이고, 그림 2-30(55쪽)은 `node start.mjs --help 20`으로 연 20장 상세 도움말이다. 터미널에서 `node start.mjs --open 06`을 입력하면 6장 장바구니 코드가 열리고, `node start.mjs --open all`을 입력하면 1~20장의 대표 파일을 함께 볼 수 있다.

3장은 61쪽, 4장의 예제 꺼내기는 75쪽, 첫 앱 패키지 설치는 79쪽, PC 미리보기는 83쪽이다. 12장은 223쪽에서 시작한다.

16.5절의 284~285쪽에서는 `use-accessibility-focus.web.ts`의 코드를 읽고 PC 브라우저에서 키보드로 실습한다. 예시 상품을 열 때 장보기 제목으로, 다시 풀 때 답 입력칸으로, 계산을 마칠 때 영수증 제목으로 초점이 이동하는지 확인한다.

16.6절은 286쪽에서 시작한다. 287쪽의 VS Code 탐색기에서 버튼 파일을 열고, 287~290쪽에서 전체 코드 61줄을 확인한다. 실제 VS Code 화면에서 App.tsx의 버튼을 불러오는 6행(291쪽)과 장보기 화면에 버튼을 넣는 211행(292쪽)을 차례로 확인한다. 상품 준비 화면(293~294쪽)과 영수증 화면(295~296쪽)에서도 어떤 줄에 버튼을 불러오고 배치하는지 VS Code 화면으로 확인한다. Android에서 TalkBack을 켜고 다시 끄는 실습은 297~298쪽에 있다. HTML판에서 파일 전체 코드를 복사할 수 있다. 364쪽에서는 설정을 다녀온 후 장바구니를 확인한다. 이전 ZIP에서 시작했다면 397쪽의 Git Bash 명령으로 바로가기가 포함된 앱을 받을 수 있다. HTML에서는 그림을 눌러 확대할 수 있다.

20.7절(373~381쪽)에서 20장 완성본을 열어 ‘오늘의 놀이돈’과 ‘낼 놀이돈 고르기’에서 각각 50,000원을 고른다. 사과 두 개와 우유 한 팩을 담은 뒤 50,000원권과 10,000원권으로 각각 계산해 두 영수증의 거스름돈과 남은 예산을 비교한다. 377~380쪽의 코딩 실습에서는 연습용 20장 사본에서 두 선택지를 잠시 뺀 뒤, VS Code에서 예산 파일 2행과 지폐 파일 7행에 금액을 하나씩 입력하고 저장한다. 단계별로 화면을 비교한 뒤 결제와 테스트까지 확인한다. 이전 ZIP으로 시작한 독자는 부록 C.2(398쪽)의 QR이나 링크로 최신 장별 실습 예제 ZIP을 받아 20장을 실행할 수 있다.

종이책 2쪽의 QR과 주소를 열면 장별 실습 ZIP과 상품 12개 CSV를 받을 수 있다. 395쪽의 QR은 상품·가격 SQL로 연결된다. 전자판은 HTML 본문의 저장 링크와 PDF 첨부 파일로 장별 예제 ZIP을 제공한다.

이 책의 PDF·HTML에 첨부한 ZIP에는 1장의 기획 활동지, 2장의 도구 점검표, 3~20장의 개발 예제가 들어 있다. 20장에서 완성 앱 소스코드를 꺼낼 수 있다. 처음 압축을 푼 폴더에서 예제 생성·설치·웹 실행을 한 줄로 진행하려면 부록 C.1(392쪽)을 본다. 393쪽에는 20장 도움말을 여는 두 명령이 함께 있다. `start.mjs`가 보이는 폴더에서는 `node start.mjs --help 20`을, `work/ch20/apps/mobile`에서는 `node ../../../../start.mjs --help 20`을 입력한다. 이미 준비한 20장 앱은 이 앱 폴더의 PowerShell에서 `npm.cmd run web` 한 줄로 다시 연다. 394쪽은 예제 최상위 폴더에서 다음 장을 꺼내는 절차다.

## 개발 당시의 가제와 계획

아이와 함께 만드는 Android 시장놀이 앱 — 기획부터 Google Play 출시까지

2026-11-17 사용자 요청으로 iOS 개발을 중단하고 Android·Google Play 출시로 범위를 좁혔다. 이후 계획과 검사 안내는 새 범위를 따르며, 이미 작성한 장의 당시 계획·iOS 번들 검사 결과·자동 보고서는 고치지 않고 보존한다.

범위 변경 직후 npm run typecheck, npm run lint, npm run export:check가 모두 통과했고, 번들은 Android 645개 모듈·개발용 웹 251개 모듈만 생성했으며 iOS 번들은 생성하지 않았다. 당시 실기기 재검사·신규 APK 빌드·별도 커밋은 만들지 않았다. 이후 Android 배포 설정·검사 앱 분리와 함께 설정 검사·Expo Go 전체 회귀를 통과해 a6d9bb4에 기록했다.

## 매 단계에 남길 기록

- 날짜와 목표
- 사용한 도구의 실제 버전
- 변경 파일과 선택한 이유
- 실제 실행 명령
- 실패한 부분과 해결 과정
- 실행한 검증 / 아직 하지 않은 검증
- 화면 캡처(개인정보·토큰 제외)
- 코드 기준 태그와 실제 커밋 ID
- 다음 장에서 풀 문제

각 장에는 해당 단계의 코드 커밋 ID를 기록합니다. 태그는 사용자가 실제로 만든 경우에만 기록합니다. 원고를 정리하는 커밋과 원고에서 설명하는 코드 커밋은 서로 다를 수 있으며, 실제 이력은 아래 명령으로 확인합니다.

bash
git log --oneline --decorate


독자가 이전 장을 실행할 때 원래 작업 폴더를 변경하지 않으려면 별도 폴더에 저장소를 복제한 뒤 원하는 커밋 또는 사용자가 만든 태그를 체크아웃합니다. 패키지는 해당 장의 package-lock.json을 기준으로 npm ci로 설치합니다.

원고의 목표는 실제로 수행한 개발 과정을 재현하는 것입니다. 설치·테스트·심사를 하지 않은 상태에서 성공한 것처럼 서술하지 않습니다.
