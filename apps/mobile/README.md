# 꼬마 시장 — 모바일 앱

Expo SDK 58 / React Native / TypeScript 앱입니다. 자체 예시 상품 6개와 장바구니를 구현했습니다. 담기·수량 조절·품목 삭제·전체 비우기·합계를 확인할 수 있습니다. 한 종류에 최대 9개이며, 새로고침하면 장바구니가 초기화됩니다. 오늘의 놀이돈 10,000원을 기준으로 남을 돈과 부족한 돈을 표시합니다. 낼 놀이돈 1,000원·5,000원·10,000원 중 하나를 고르고 물건값에 충분한지 확인할 수 있습니다. 충분한 돈을 고르면 받을 거스름돈과 계산식을 표시합니다. 거스름돈 맞히기, DB와 실제 가격 연동은 이후 단계입니다.

## Windows Git Bash에서 실행

저장소 루트에서:

```bash
cd apps/mobile
npm ci
npm start
```

이미 설치를 마친 작업 폴더에서는 npm ci를 매번 실행할 필요가 없습니다. PowerShell을 사용할 때는 npm 대신 npm.cmd, npx 대신 npx.cmd로 실행할 수 있습니다.

## 갤럭시 / Android에서 보기

1. [Expo 공식 설치 안내](https://docs.expo.dev/get-started/set-up-your-environment/)에서 Expo Go를 설치합니다.
2. PC와 휴대전화를 같은 Wi-Fi에 연결합니다.
3. 위 명령으로 개발 서버를 실행합니다.
4. Expo Go에서 QR 스캔을 열고 PC 터미널의 QR을 읽습니다.
5. 꼬마 시장, 예시 상품 6개, 각 상품의 담기 버튼과 하단 합계를 확인합니다.
6. 종료할 때 서버 터미널에서 Ctrl+C를 누릅니다.

다른 미리보기 서버가 이미 8081 포트를 사용한다면 기존 서버를 종료하거나 npm start -- --port 8082로 다른 포트를 사용합니다. 휴대전화 실행에는 --localhost 옵션을 사용하지 않습니다.

연결 실패 시 같은 네트워크인지, VPN·공용 Wi-Fi의 기기 간 연결 제한이 있는지 확인합니다. SDK 호환 오류가 있으면 [공식 Expo Go 다운로드 페이지](https://expo.dev/go)에서 SDK 58 지원 여부를 확인하고 프로젝트와 앱 버전을 맞춥니다.

## iPhone에서 보기

PC와 같은 Wi-Fi에서 iPhone 카메라로 QR을 읽습니다. 현재 공식 안내에 따르면 iPhone 실기기는 Expo CLI와 Expo Go에 같은 Expo 계정으로 로그인해야 합니다.

```bash
npx expo login
```

로그인은 사용자가 직접 수행합니다. [공식 iPhone 로그인 안내](https://docs.expo.dev/troubleshooting/expo-go-sign-in-required/)

## PC 브라우저와 코드 검사

```bash
npm run web
```

브라우저 미리보기는 실제 Android·iPhone 테스트를 대신하지 않습니다.

```bash
npm test
npm run typecheck
npm run lint
npm run export:check
npx expo-doctor
```

export:check는 Android·iOS·웹의 JavaScript 번들을 생성합니다. APK/AAB/IPA 생성이나 스토어 제출은 아닙니다.

## 장바구니 확인

사과의 담기를 누른 뒤 +를 한 번 눌러 2개를 담고, 우유를 1개 담습니다. 화면 하단이 총 3개·5,500원인지 확인합니다. 상품의 −로 하나씩 빼고, 목록 아래 내 장바구니의 빼기 또는 장바구니 비우기로 삭제할 수 있습니다.

계산 테스트 9개와 코드 검사, Android·iOS·웹 번들, 브라우저 동작을 검증했습니다. 2026-11-11에 사용자가 **갤럭시에서 사과 2개·우유 1개를 담아 총 3개·5,500원 표시**를 확인했습니다. 같은 날 수량을 하나씩 줄여 마지막 상품을 제거하고 0개·0원과 빈 장바구니 안내가 표시되는 것도 확인했습니다. 사과 9개·13,500원, 수량 제한 안내와 더하기 버튼 비활성화 및 추가 담기 차단도 확인했습니다. 품목 전체 삭제 버튼으로 사과 9개를 빼고 우유만 1개·2,500원으로 유지되는 것도 확인했습니다. 전체 비우기 뒤 0개·0원과 빈 장바구니 안내가 표시되고 우유·당근의 담기 버튼이 복원되는 것도 확인했습니다. 새로고침 후 0개·0원과 빈 장바구니 안내가 표시되고 사과의 담기 버튼이 복원되는 것도 확인해, 이번 단계의 갤럭시 기본 동작 검증을 마쳤습니다. iPhone 실기기 검증은 아직 하지 않았습니다. 구현 과정과 검증은 [책 2장](../../docs/book/chapters/02-shopping-cart.md)에 기록합니다.

## 놀이돈 예산 확인

오늘의 놀이돈은 현재 10,000원으로 고정되어 있습니다. 사과 2개와 우유 1개를 담으면 합계 5,500원과 남을 돈 4,500원이 표시됩니다. 합계가 10,000원이면 남을 돈 0원과 “놀이돈에 딱 맞아요!”가 보입니다. 예산을 넘으면 부족한 돈과 “물건을 조금 빼 볼까요?”를 표시하며, 상품을 줄이거나 비우면 잔액도 함께 갱신됩니다.

예산을 넘는 금액을 직접 비교할 수 있도록 담기는 계속 허용합니다. 이 단계의 남을 돈은 선택한 물건을 모두 샀다고 가정한 예산 잔액이며, 지불 후 돌려받는 거스름돈 문제는 다음 단계입니다. 새로고침하면 장바구니는 비워지고 남을 돈은 10,000원으로 돌아갑니다.

기존 장바구니 9개와 예산 8개를 합친 테스트 17개, 타입·ESLint 검사, Android·iOS·웹 번들, 390px·320px 브라우저 동작을 확인했습니다. 2026-11-11에 사용자가 **갤럭시에서 오늘의 놀이돈 10,000원과 사과 2개·우유 1개의 합계 5,500원·남을 돈 4,500원**을 확인했습니다. 총 5개·10,000원에서 남을 돈 0원과 “놀이돈에 딱 맞아요!” 안내도 확인했습니다. 당근 1개 추가 후 총 6개·11,000원에서 부족한 돈 1,000원과 “물건을 조금 빼 볼까요?” 안내도 확인했습니다. 상품을 줄이면 5개·10,000원·남을 돈 0원을 거쳐 4개·8,500원·남을 돈 1,500원으로 돌아오고 안내 문구도 바뀌는 것을 확인했습니다. 전체 비우기 후 0개·0원·남을 돈 10,000원과 빈 장바구니 안내 및 “놀이돈 안에서 장을 봐요.” 문구도 확인했습니다. 새로고침 후 0개·0원·남을 돈 10,000원으로 돌아오고 빈 장바구니 안내와 사과의 담기 버튼이 표시되는 것도 확인해, 이번 예산 단계의 갤럭시 기본 동작 검증을 마쳤습니다. iPhone 실기기 검증은 아직 하지 않았습니다. [책 3장](../../docs/book/chapters/03-play-money.md)에 구현 이유와 검증 결과를 기록합니다.

## 낼 놀이돈 선택 확인

목록 아래 “낼 놀이돈 고르기”에서 1,000원·5,000원·10,000원 중 하나를 고릅니다. 다른 금액을 누르면 선택을 교체하며 누적하지 않습니다. 선택한 금액이 적으면 더 필요한 돈을 안내하고, 충분하면 “이 돈으로 계산할 수 있어요!”라고 표시합니다. 돈 선택은 예산 잔액을 바꾸지 않습니다.

먼저 사과 2개와 우유 1개를 담아 합계 5,500원으로 만든 다음 5,000원을 선택합니다. “선택한 돈 5,000원”과 “500원이 더 필요해요.”가 보이고, 하단의 남을 돈은 4,500원으로 유지되는지 확인합니다.

선택 취소는 돈 선택만 지우며, 상품 구성이나 수량을 바꾸면 돈을 다시 고르게 됩니다. 빈 장바구니와 예산 초과 상태에서는 금액 버튼이 비활성화됩니다. 실제 결제 완료나 거스름돈 퀴즈는 아직 없습니다.

돈 선택 15개를 포함한 전체 테스트 32개, 타입·ESLint 검사, Android·iOS·웹 번들, 390px·320px 브라우저의 선택·교체·취소·초기화·비활성 상태를 확인했습니다. 2026-11-12에 사용자가 갤럭시에서 5,000원 버튼의 선택됨 표시와 선택한 돈 5,000원, “500원이 더 필요해요.” 안내, 남을 돈 4,500원 유지를 확인했습니다. 같은 날 10,000원으로 선택을 바꾸면 5,000원 버튼이 고르기로 돌아오고, 선택한 돈 10,000원과 “이 돈으로 계산할 수 있어요!” 안내가 표시되며 3개·5,500원·남을 돈 4,500원이 유지되는 것도 확인했습니다. 선택 취소 후 “아직 안 골랐어요”와 “낼 놀이돈을 하나 골라 주세요.”가 표시되고, 모든 금액 버튼이 고르기로 돌아오며 선택 취소 버튼이 사라지는 것도 확인했습니다. 이때도 3개·5,500원과 남을 돈 4,500원이 유지되었습니다. 10,000원을 선택한 뒤 사과를 한 개 더 담으면 4개·7,000원·남을 돈 3,000원으로 바뀌고, 미선택 안내·모든 금액 버튼의 고르기 표시·선택 취소 버튼 사라짐으로 돈 선택이 초기화되는 것도 확인했습니다. 식빵 한 봉을 더 담고 10,000원을 선택하면 5개·10,000원·남을 돈 0원과 “놀이돈에 딱 맞아요!”, 10,000원 버튼의 선택됨 표시와 “이 돈으로 계산할 수 있어요!”가 함께 표시되는 것도 확인했습니다. 당근 한 개를 더 담으면 6개·11,000원·부족한 돈 1,000원과 미선택·물건을 빼라는 안내가 표시되고, 모든 금액 버튼이 흐려져 10,000원을 눌러도 선택되지 않으며 선택됨 표시와 선택 취소 버튼도 사라지는 것을 확인했습니다. 당근을 빼고 10,000원을 선택하면 총 5개·10,000원·남을 돈 0원과 “놀이돈에 딱 맞아요!”가 표시되고, 금액 버튼이 다시 활성화되어 10,000원 선택됨·선택한 돈 10,000원·“이 돈으로 계산할 수 있어요!”가 보이는 것도 확인했습니다. 전체 비우기 후 0개·0원·남을 돈 10,000원과 빈 장바구니·미선택·먼저 물건을 담으라는 안내가 표시되고, 모든 금액 버튼이 비활성화되어 10,000원을 눌러도 선택되지 않으며 선택됨 표시와 선택 취소 버튼이 사라지는 것도 확인했습니다. 새로고침 후 초기화와 iPhone 실기기·화면 읽기 기능은 아직 확인하지 않았습니다. [책 3장 보충](../../docs/book/chapters/03a-payment-selection.md)에 실제 검증 결과를 기록합니다.

## 받을 거스름돈 확인

충분한 돈을 고르면 기존 선택 안내 아래에 “받을 거스름돈”과 계산식이 나타납니다. 사과 2개·우유 1개의 물건값 5,500원에 10,000원을 고르면 “10,000원 − 5,500원 = 4,500원”을 보여 줍니다. 정확히 맞는 금액이면 거스름돈 0원을 표시합니다.

당근 1개의 물건값 1,000원에 5,000원을 고르면 받을 거스름돈은 4,000원이고, 하단의 예산에서 남을 돈은 9,000원입니다. 돈 선택은 예산을 차감하지 않습니다. 부족한 돈으로 바꾸거나 선택을 취소하거나 상품을 바꾸면 이전 거스름돈도 사라집니다.

2026-11-12 기준 이전 돈 선택·자동화 작업은 `8309377`로 커밋했고, 갤럭시 전체 자동 검사와 Expo Go 재실행 초기화를 확인했습니다. 위의 수동 새로고침 미확인 기록과 구분합니다. 이번 거스름돈 기능의 구현 이유와 최종 검증 확인 방법은 [거스름돈 계산 기록](../../docs/book/chapters/03c-change-calculation.md)을 참고합니다.

## 갤럭시 자동 검사

2026-11-12 사용자 요청으로 반복 검사·기록·커밋을 자동화합니다. USB 디버깅으로 연결된 갤럭시에서 Maestro가 실제 화면을 조작합니다. 설치·연결과 최초 자동 실행 결과는 [자동 검사 안내](../../docs/04-device-automation.md)를 참고합니다.

```bash
npm run device:doctor
npm run verify:device
```

모든 검사 성공 후 검증 기록과 확인한 변경만 자동 커밋합니다. 커밋 없이 확인하려면 npm run verify:device:check를 사용합니다. 실제 검사 성공 여부는 실행 후 생성되는 docs/book/verification/latest-android.md에서 확인합니다. 연결만 확인한 device:doctor 결과와 실기기 화면 검사 성공은 구분합니다.

## 개발 기준

- 최초 SDK 57 템플릿에서 시작했으나, 갤럭시에 설치된 Expo Go가 SDK 58용임을 확인해 프로젝트를 SDK 58로 올렸습니다.
- 설치 버전은 package-lock.json으로 재현합니다.
- 추가 패키지는 npx expo install을 통해 SDK에 맞춥니다.
- 현재 화면 이동은 없습니다. 여러 화면을 도입할 때 Expo Router를 사용합니다.
- 실제 가격·로고·사진을 임의 수집한 데이터는 포함하지 않습니다.
- 아이콘은 Expo 템플릿 자산입니다. 출시 단계에서 전용 아이콘과 스토어 식별자를 정합니다.

검증 결과와 의존성 경고는 [책 1장](../../docs/book/chapters/01-first-app.md)에 기록했습니다.

SDK 58 업데이트 과정과 최신 검증 결과는 [Expo Go 호환 오류 해결 기록](../../docs/book/chapters/01a-expo-go-sdk58.md)에 있습니다.
