# 꼬마 시장 — Android 앱

Expo SDK 58 / React Native / TypeScript 앱입니다. 자체 예시 상품 12개와 분류별 선택·장바구니를 구현했습니다. 전체 / 과일·채소 / 유제품·달걀 / 빵·간식으로 목록을 바꿀 수 있으며, 분류를 바꿔도 담은 물건·선택한 돈·퀴즈는 유지됩니다. 담기·수량 조절·품목 삭제·전체 비우기·합계를 확인할 수 있습니다. 한 종류에 최대 9개이며, 새로고침하면 장바구니가 초기화됩니다. 오늘의 놀이돈을 10,000원 또는 50,000원으로 정하면 선택한 예산을 기준으로 남을 돈과 부족한 돈을 표시합니다. 낼 돈은 예산 안에서 1,000원·5,000원·10,000원·50,000원 중 하나를 고릅니다. 충분한 돈을 고르면 거스름돈을 입력해 맞히는 문제가 나옵니다. 정답을 맞히면 받을 거스름돈과 계산식을 공개하고, 딱 맞게 낸 경우에도 0원을 답으로 입력합니다. Supabase에서 자체 예시 목록을 읽으며, 원격 조회가 실패하면 재시도하거나 내장 예시를 직접 선택할 수 있습니다. 실제 가격의 비공개 기록을 살펴보는 개발용 미리보기와 일반 사용자에게 공개하는 단계는 구분합니다.

2026-11-17 사용자 요청으로 iOS 개발을 중단했습니다. 앞으로 Android 앱과 Google Play 배포를 준비하며 웹은 개발 중 미리보기·검사용으로 사용합니다. 아래 과거 검증 기록의 iOS 번들 결과와 미확인 항목은 당시 사실로 보존합니다.

## Windows Git Bash에서 실행

저장소 루트에서:

```bash
cd apps/mobile
npm ci
npm start
```

이미 설치를 마친 작업 폴더에서는 npm ci를 매번 실행할 필요가 없습니다. PowerShell을 사용할 때는 npm 대신 npm.cmd, npx 대신 npx.cmd로 실행할 수 있습니다.

## 갤럭시 / Android에서 보기

1. [Expo 공식 설치 안내](https://docs.expo.dev/get-started/set-up-your-environment/)에서 Expo Go를 설치합니다.
2. PC와 휴대전화를 같은 Wi-Fi에 연결합니다.
3. 위 명령으로 개발 서버를 실행합니다.
4. Expo Go에서 QR 스캔을 열고 PC 터미널의 QR을 읽습니다.
5. 연결 설정이 있으면 상품을 불러온 뒤 목록을 표시합니다. 기다리는 중이나 설정 없음·조회 실패 화면에서 **예시 상품으로 바로 놀이하기**를 누르면 내장 예시 12개로 시작할 수 있습니다. 상품의 담기 버튼과 하단 합계를 확인합니다.
6. 종료할 때 서버 터미널에서 Ctrl+C를 누릅니다.

다른 미리보기 서버가 이미 8081 포트를 사용한다면 기존 서버를 종료하거나 npm start -- --port 8082로 다른 포트를 사용합니다. 같은 Wi-Fi에서 QR로 연결하는 이 방식에서는 --localhost 옵션을 사용하지 않습니다. 아래의 전용 USB 미리보기 실행기는 휴대전화의 USB 연결을 준비하므로 별도로 동작합니다.

연결 실패 시 같은 네트워크인지, VPN·공용 Wi-Fi의 기기 간 연결 제한이 있는지 확인합니다. SDK 호환 오류가 있으면 [공식 Expo Go 다운로드 페이지](https://expo.dev/go)에서 SDK 58 지원 여부를 확인하고 프로젝트와 앱 버전을 맞춥니다.

## 실제 가격 개발용 미리보기

사용자가 확인한 실제 가격의 비공개 DB 기록을 본인 갤럭시에서 읽기 전용으로 살펴보는 기능입니다. 컴퓨터와 USB 연결이 필요합니다. 일반 `npm start`의 공개 예시 목록과는 별도 실행 방식입니다.

1. 갤럭시를 USB로 연결하고 USB 디버깅을 허용한 뒤 화면 잠금을 해제합니다.
2. DB에서 새로 조회해 만든 저장소 루트의 `.artifacts/catalog/private-preview.json`이 준비되어 있는지 확인합니다. DB 조회 후 24시간 이내이고 앱 설정과 같은 프로젝트의 자료여야 합니다. 이 파일은 앱 코드나 Git에 넣지 않습니다.
3. 모바일 앱 폴더의 Git Bash에서 전용 실행기를 시작합니다.

```bash
npm run start:price-preview
```

추가 인자 없이 실행하면 연결한 갤럭시의 Expo Go가 열립니다. 앱에서 **실제 가격 미리보기 · 개발용**을 누릅니다. **확인 당시 가격** 창에서 상품명·규격·가격·SSG.COM 이마트 온라인 출처·확인 시각을 읽습니다. 판매 상태는 **재고 미확인** 또는 **확인 당시 품절**처럼 표시합니다. DB에서 자료를 다시 읽은 시각은 상품 페이지의 가격을 확인한 시각과 다릅니다. 이전 관측을 현재 판매 가격처럼 갱신하지 않습니다.

미리보기에는 장바구니 담기나 실제 구매 기능이 없습니다. 닫기와 Android 뒤로가기로 기존 놀이에 돌아오며, 예시 상품의 장바구니 상태를 유지합니다. 자료가 없거나 연결에 실패하면 안내를 표시하고, 예시 자료를 실제 가격처럼 대신 보여 주지 않습니다.

**PC 기록 다시 불러오기**는 PC에 준비된 같은 DB 조회 자료를 다시 읽습니다. 이 버튼이 SSG.COM의 가격을 새로 수집하거나 DB를 자동 갱신하지는 않습니다. 내부 재확인 기한이 지난 관측에는 해당 안내가 표시됩니다.

전용 실행기는 컴퓨터 내부 주소와 USB 연결을 사용합니다. 가격 서버는 8092, Expo 서버는 8093 포트를 사용하며 기존 8082 개발 서버와 별도로 동작합니다. 자료 파일이나 연결 설정이 달라지면 실행을 종료하므로 다시 시작해야 합니다. 마칠 때는 전용 터미널에서 Ctrl+C를 누릅니다. 사용자가 이미 만든 연결은 보존하고, 실행기가 만든 서버와 연결만 정리합니다. 자동 검사가 끝나면 검사 서버도 종료되므로 다시 살펴볼 때는 위 명령을 사용합니다.

실제 가격 자료·관리자 키를 배포 앱에 넣지 않습니다. 일반 사용자용 가격 공개와 자동 갱신은 후속 단계입니다. [구현과 최종 검증 결과](../../docs/book/chapters/04c-real-price-preview.md)

## 기다리지 않고 예시 상품으로 놀이하기

**가게 물건을 가져오고 있어요**가 표시될 때 **예시 상품으로 바로 놀이하기**를 누릅니다. 연결 오류가 날 때까지 기다리지 않고 앱에 준비된 예시 12개로 장보기를 시작합니다. 상품 위의 **앱에 준비된 예시 상품으로 놀고 있어요.** 안내로 출처를 확인할 수 있습니다.

예시를 고르면 진행 중인 상품 조회를 취소하고, 늦게 도착한 원격 목록이나 오류는 무시합니다. 예시로 시작한 뒤의 장바구니·돈 선택·거스름돈 문제·영수증은 그 예시 가격을 계속 사용합니다. **다시 장보기**도 같은 예시로 빈 장바구니와 놀이돈 10,000원에서 시작합니다.

이 기능은 이미 실행된 앱에서 DB 연결을 기다리지 않고 시작하는 선택지입니다. Expo Go가 앱 코드를 처음 받아오는 데 필요한 개발 서버 연결이나 설치형 앱의 오프라인 첫 실행 검증과는 구분합니다. 마지막 원격 목록을 저장하는 영구 캐시는 추가하지 않습니다. [구현 과정과 검증 상태](../../docs/book/chapters/05-offline-sample-play.md)

2026-11-13 코드 검사에서 새 검사 18개를 포함한 앱 검사 125개와 타입·ESLint·세 플랫폼 번들이 통과했습니다. 최초 연결 점검은 USB 디버깅 승인 부족으로 멈췄고, 이후 사용자가 승인해 연결과 잠금 해제를 확인했습니다. 전체 실기기 결과는 [검증 기록](../../docs/book/verification/latest-android.md)의 검사 시작 HEAD `f6f4ccb`와 두 검사 단계의 실제 결과로 확인합니다. 연결 확인만으로 실기기 성공을 뜻하지 않습니다.

## 장바구니 확인

사과의 담기를 누른 뒤 +를 한 번 눌러 2개를 담고, 우유를 1개 담습니다. 화면 하단이 총 3개·5,500원인지 확인합니다. 상품의 −로 하나씩 빼고, 목록 아래 내 장바구니의 빼기 또는 장바구니 비우기로 삭제할 수 있습니다.

계산 테스트 9개와 코드 검사, Android·iOS·웹 번들, 브라우저 동작을 검증했습니다. 2026-11-11에 사용자가 **갤럭시에서 사과 2개·우유 1개를 담아 총 3개·5,500원 표시**를 확인했습니다. 같은 날 수량을 하나씩 줄여 마지막 상품을 제거하고 0개·0원과 빈 장바구니 안내가 표시되는 것도 확인했습니다. 사과 9개·13,500원, 수량 제한 안내와 더하기 버튼 비활성화 및 추가 담기 차단도 확인했습니다. 품목 전체 삭제 버튼으로 사과 9개를 빼고 우유만 1개·2,500원으로 유지되는 것도 확인했습니다. 전체 비우기 뒤 0개·0원과 빈 장바구니 안내가 표시되고 우유·당근의 담기 버튼이 복원되는 것도 확인했습니다. 새로고침 후 0개·0원과 빈 장바구니 안내가 표시되고 사과의 담기 버튼이 복원되는 것도 확인해, 이번 단계의 갤럭시 기본 동작 검증을 마쳤습니다. iPhone 실기기 검증은 아직 하지 않았습니다. 구현 과정과 검증은 [책 2장](../../docs/book/chapters/02-shopping-cart.md)에 기록합니다.

## 놀이돈 예산 확인

오늘의 놀이돈은 10,000원에서 시작하며 50,000원으로 바꿀 수 있습니다. 예산을 바꾸면 장바구니는 유지하고 낼 돈과 퀴즈 답은 다시 고릅니다. 기본 예산에서 사과 2개와 우유 1개를 담으면 합계 5,500원과 남을 돈 4,500원이 표시됩니다. 합계가 10,000원이면 남을 돈 0원과 “놀이돈에 딱 맞아요!”가 보입니다. 예산을 넘으면 부족한 돈과 “물건을 조금 빼 볼까요?”를 표시하며, 상품을 줄이거나 비우면 잔액도 함께 갱신됩니다.

예산을 넘는 금액을 직접 비교할 수 있도록 담기는 계속 허용합니다. 이 단계의 남을 돈은 선택한 물건을 모두 샀다고 가정한 예산 잔액이며, 지불 후 돌려받는 거스름돈 문제는 다음 단계입니다. 새로고침하면 장바구니는 비워지고 남을 돈은 10,000원으로 돌아갑니다.

기존 장바구니 9개와 예산 8개를 합친 테스트 17개, 타입·ESLint 검사, Android·iOS·웹 번들, 390px·320px 브라우저 동작을 확인했습니다. 2026-11-11에 사용자가 **갤럭시에서 오늘의 놀이돈 10,000원과 사과 2개·우유 1개의 합계 5,500원·남을 돈 4,500원**을 확인했습니다. 총 5개·10,000원에서 남을 돈 0원과 “놀이돈에 딱 맞아요!” 안내도 확인했습니다. 당근 1개 추가 후 총 6개·11,000원에서 부족한 돈 1,000원과 “물건을 조금 빼 볼까요?” 안내도 확인했습니다. 상품을 줄이면 5개·10,000원·남을 돈 0원을 거쳐 4개·8,500원·남을 돈 1,500원으로 돌아오고 안내 문구도 바뀌는 것을 확인했습니다. 전체 비우기 후 0개·0원·남을 돈 10,000원과 빈 장바구니 안내 및 “놀이돈 안에서 장을 봐요.” 문구도 확인했습니다. 새로고침 후 0개·0원·남을 돈 10,000원으로 돌아오고 빈 장바구니 안내와 사과의 담기 버튼이 표시되는 것도 확인해, 이번 예산 단계의 갤럭시 기본 동작 검증을 마쳤습니다. iPhone 실기기 검증은 아직 하지 않았습니다. [책 3장](../../docs/book/chapters/03-play-money.md)에 구현 이유와 검증 결과를 기록합니다.

## 낼 놀이돈 선택 확인

목록 아래 “낼 놀이돈 고르기”에서 예산 안에서 1,000원·5,000원·10,000원·50,000원 중 하나를 고릅니다. 50,000원 지폐를 사용하려면 화면 위 ‘오늘의 놀이돈’에서 50,000원을 선택합니다. 다른 금액을 누르면 선택을 교체하며 누적하지 않습니다. 선택한 금액이 적으면 더 필요한 돈을 안내하고, 충분하면 “이 돈으로 계산할 수 있어요!”라고 표시합니다. 돈 선택은 예산 잔액을 바꾸지 않습니다.

먼저 사과 2개와 우유 1개를 담아 합계 5,500원으로 만든 다음 5,000원을 선택합니다. “선택한 돈 5,000원”과 “500원이 더 필요해요.”가 보이고, 하단의 남을 돈은 4,500원으로 유지되는지 확인합니다.

선택 취소는 돈 선택만 지우며, 상품 구성이나 수량을 바꾸면 돈을 다시 고르게 됩니다. 빈 장바구니와 예산 초과 상태에서는 금액 버튼이 비활성화됩니다. 거스름돈 맞히기와 놀이 계산 완료·영수증은 아래 안내를 참고합니다.

돈 선택 15개를 포함한 전체 테스트 32개, 타입·ESLint 검사, Android·iOS·웹 번들, 390px·320px 브라우저의 선택·교체·취소·초기화·비활성 상태를 확인했습니다. 2026-11-12에 사용자가 갤럭시에서 5,000원 버튼의 선택됨 표시와 선택한 돈 5,000원, “500원이 더 필요해요.” 안내, 남을 돈 4,500원 유지를 확인했습니다. 같은 날 10,000원으로 선택을 바꾸면 5,000원 버튼이 고르기로 돌아오고, 선택한 돈 10,000원과 “이 돈으로 계산할 수 있어요!” 안내가 표시되며 3개·5,500원·남을 돈 4,500원이 유지되는 것도 확인했습니다. 선택 취소 후 “아직 안 골랐어요”와 “낼 놀이돈을 하나 골라 주세요.”가 표시되고, 모든 금액 버튼이 고르기로 돌아오며 선택 취소 버튼이 사라지는 것도 확인했습니다. 이때도 3개·5,500원과 남을 돈 4,500원이 유지되었습니다. 10,000원을 선택한 뒤 사과를 한 개 더 담으면 4개·7,000원·남을 돈 3,000원으로 바뀌고, 미선택 안내·모든 금액 버튼의 고르기 표시·선택 취소 버튼 사라짐으로 돈 선택이 초기화되는 것도 확인했습니다. 식빵 한 봉을 더 담고 10,000원을 선택하면 5개·10,000원·남을 돈 0원과 “놀이돈에 딱 맞아요!”, 10,000원 버튼의 선택됨 표시와 “이 돈으로 계산할 수 있어요!”가 함께 표시되는 것도 확인했습니다. 당근 한 개를 더 담으면 6개·11,000원·부족한 돈 1,000원과 미선택·물건을 빼라는 안내가 표시되고, 모든 금액 버튼이 흐려져 10,000원을 눌러도 선택되지 않으며 선택됨 표시와 선택 취소 버튼도 사라지는 것을 확인했습니다. 당근을 빼고 10,000원을 선택하면 총 5개·10,000원·남을 돈 0원과 “놀이돈에 딱 맞아요!”가 표시되고, 금액 버튼이 다시 활성화되어 10,000원 선택됨·선택한 돈 10,000원·“이 돈으로 계산할 수 있어요!”가 보이는 것도 확인했습니다. 전체 비우기 후 0개·0원·남을 돈 10,000원과 빈 장바구니·미선택·먼저 물건을 담으라는 안내가 표시되고, 모든 금액 버튼이 비활성화되어 10,000원을 눌러도 선택되지 않으며 선택됨 표시와 선택 취소 버튼이 사라지는 것도 확인했습니다. 새로고침 후 초기화와 iPhone 실기기·화면 읽기 기능은 아직 확인하지 않았습니다. ## 받을 거스름돈 확인

거스름돈 문제의 정답을 맞히면 기존 선택 안내 아래에 “받을 거스름돈”과 계산식이 나타납니다. 사과 2개·우유 1개의 물건값 5,500원에 10,000원을 고르면 “10,000원 − 5,500원 = 4,500원”을 보여 줍니다. 정확히 맞는 금액이면 거스름돈 0원을 표시합니다.

당근 1개의 물건값 1,000원에 5,000원을 고르면 받을 거스름돈은 4,000원이고, 하단의 예산에서 남을 돈은 9,000원입니다. 돈 선택은 예산을 차감하지 않습니다. 부족한 돈으로 바꾸거나 선택을 취소하거나 상품을 바꾸면 이전 거스름돈도 사라집니다.

2026-11-12 기준 이전 돈 선택·자동화 작업은 `8309377`로 커밋했고, 갤럭시 전체 자동 검사와 Expo Go 재실행 초기화를 확인했습니다. 위의 수동 새로고침 미확인 기록과 구분합니다. 이번 거스름돈 기능의 구현 이유와 최종 검증 확인 방법은 [거스름돈 계산 기록](../../docs/book/chapters/03c-change-calculation.md)을 참고합니다.

## 거스름돈 맞히기

물건을 담고 충분한 놀이돈을 고르면 “거스름돈 맞히기”가 나타납니다. 답을 숫자로 입력하고 “정답 확인”을 누릅니다. 빈 답은 입력 안내를 보여 주고, 오답은 힌트를 읽고 고칠 수 있습니다. 거스름돈이 없으면 0을 입력합니다.

정답을 맞힌 뒤 거스름돈과 계산식을 공개합니다. 푸는 동안에는 하단의 남을 돈을 ?원으로 가리며, 정답 후 원래 잔액을 보여 줍니다. “다시 풀기”는 같은 물건·놀이돈으로 입력만 초기화합니다. 물건이나 낼 돈을 바꾸면 이전 답과 채점 결과도 사라집니다.

정답 입력 후에는 입력칸을 잠급니다. 다시 풀기를 누르면 새로 입력할 수 있습니다. 키보드가 열린 상태에서도 채점 버튼을 누를 수 있으며 채점 뒤에는 키보드가 닫힙니다. [구현과 검증 기록](../../docs/book/chapters/03d-change-quiz.md)을 참고하세요.

## 계산 완료와 영수증

정답을 맞힌 뒤 돈 고르기 영역 끝의 **계산 완료**를 누릅니다. 영수증에는 산 물건의 단위·단가·수량·품목 합계, 총액, 낸 놀이돈, 받은 거스름돈, 계산 후 남은 놀이돈이 나옵니다. 영수증이 표시되는 동안에는 이전 장바구니와 돈을 바꿀 수 없습니다.

사과 2개·우유 1개의 5,500원에 10,000원을 내면 거스름돈과 남은 돈은 각각 4,500원입니다. 당근 1,000원에 5,000원을 내면 거스름돈은 4,000원, 남은 돈은 9,000원입니다. 정확히 내서 거스름돈이 0원인 경우도 완료할 수 있습니다.

**다시 장보기**는 빈 장바구니와 새 놀이돈 10,000원으로 돌아갑니다. 영수증은 현재 놀이에만 남으며 다시 장보기나 앱 재시작 때 사라집니다. [구현·검증 과정](../../docs/book/chapters/03e-checkout-receipt.md)을 참고하세요.

## Android 배포 설정과 검사 앱 구분

정식 Google Play 앱은 **꼬마 시장** / `com.ungjo.storeprice`, 반복 검사 앱은 **꼬마 시장 검사** / `com.ungjo.storeprice.inspection`으로 분리합니다. 표시 버전은 `1.0.0`, 현재 정식·고정 검사 앱 설정의 Android `versionCode`는 `2`입니다. EAS의 `production`은 스토어용 AAB, `inspection`은 내부 검사 APK를 준비하는 프로필입니다. 기존 `preview`는 매번 새 패키지·코드 `1`로 오프라인 첫 실행을 확인하는 별도 검사에 유지합니다.

로컬 실행은 기본 검사 설정을 사용합니다. 정식 배포 환경에 개발용 미리보기·대기 응답·실행 표시 같은 검사 설정이 섞이면 구성을 거부합니다. 버전은 저장소에서 관리하고 자동 증가는 끄므로, 같은 정식 앱의 다음 Google Play 업로드를 준비할 때 `versionCode`를 올려 기록해야 합니다.

설정 자동 검사와 기존 Expo Go 전체 놀이 회귀는 `a6d9bb4`에 포함했고 사용자가 GitHub 업로드를 확인했습니다. 당시 신규 APK/AAB는 만들지 않았습니다. [배포 설정 개발 기록](../../docs/book/chapters/07-android-release-config.md)과 해당 커밋의 실행 `20261117T104522208Z-d7b5bd39` 보고서에 결과를 보존합니다.

설정 단계에서는 EAS 클라우드의 공개 상품 연결 설정을 변경·검증하지 않았습니다. 로컬 `.env.local`은 업로드에서 제외되므로 실제 빌드에 전달한 공개 연결 설정은 빌드별 근거로 확인합니다. 정식 production 환경 준비는 후속 작업입니다.

## 고정 검사 APK 빌드와 실제 놀이 검사

버전 `1.0.0`·코드 `1`인 **꼬마 시장 검사**의 빌드와 태블릿 전체 놀이 검증은 `bf1663e`에 포함했고 사용자가 GitHub 업로드를 확인했습니다. 패키지는 고정하고 빌드마다 다른 `inspection-` 표시와 소스·APK 지문으로 현재 파일을 구분합니다. 전용 앱 복사본에 필요한 파일과 공개 상품 설정만 고정해 빌드합니다.

기본 검사에서는 앱이 없으면 새로 설치하고, 같은 패키지가 있으면 이번 APK의 SHA-256·버전이 정확히 같은 경우에만 재사용합니다. 다른 APK는 명시적인 업데이트 근거 없이 교체하지 않으며, 성공·실패 뒤에도 고정 검사 앱을 자동 삭제하지 않습니다. APK에서 상품·장바구니·예산·낼 돈·거스름돈·영수증·분류 전체 흐름을 직접 확인하고 로딩 중 예시 선택의 개발용 지연 응답 검사는 Expo Go에서 별도로 실행합니다.

[고정 검사 APK 기록](../../docs/book/chapters/07a-inspection-apk.md)과 `bf1663e`의 실행 `20261117T141319521Z-de579384` 보고서가 코드 `1` 앱의 근거입니다. 기존 nonce preview의 오프라인 첫 실행 검증과 Google Play 제출은 별도입니다.

## 전용 아이콘과 시작 화면

정식 앱은 사과·빵을 담은 짙은 초록색 장바구니, 검사 앱은 같은 그림에 주황색 **검사** 배지를 사용합니다. 배경은 `#FAF8EF`이며 Android 적응형 아이콘의 전경·단색 이미지와 `expo-splash-screen`의 시작 화면을 앱 용도에 맞춰 함께 선택합니다. 원본 이미지와 프롬프트는 [브랜드 자산 기록](../../docs/06-brand-assets.md)에 남깁니다.

이번 코드 `2` APK는 사용자가 승인한 기존 코드 `1` 검사 앱의 업데이트입니다. 과거 PASS 커밋·원본 APK·실제 설치 파일과 서명·버전을 대조한 경우에만 `adb install -r`로 갱신하며 앱 삭제나 데이터 초기화를 실행하지 않습니다. 이는 저장 데이터 전체를 바이트 단위로 비교했다는 뜻은 아닙니다. [아이콘·시작 화면 개발 기록](../../docs/book/chapters/07b-branding-apk.md)과 검사 시작 HEAD `bf1663e`인 같은 커밋의 자동 보고서에서 이번 APK의 시각·놀이 검증 결과를 확인합니다. 인터넷 차단과 TalkBack 재검사는 이번 범위에 포함하지 않습니다.

사전 업데이트는 `updated-verified`로 끝났고 APK 내부 리소스와 실제 태블릿의 앱 정보 아이콘·시작 화면을 확인했습니다. 이는 전체 놀이 회귀 통과나 모든 런처 마스크·테마 아이콘 설정의 검증을 뜻하지 않습니다. 최종 전체 검사는 이미 설치된 새 APK의 지문을 다시 대조해 진행합니다.

## 개발 기준

- 최초 SDK 57 템플릿에서 시작했으나, 갤럭시에 설치된 Expo Go가 SDK 58용임을 확인해 프로젝트를 SDK 58로 올렸습니다.
- 설치 버전은 package-lock.json으로 재현합니다.
- 추가 패키지는 npx expo install을 통해 SDK에 맞춥니다.
- 장보기와 영수증은 같은 놀이의 상태로 전환합니다. 별도 경로가 필요한 화면 이동을 도입할 때 Expo Router를 사용합니다.
- 실제 가격·로고·사진을 임의 수집한 데이터는 포함하지 않습니다.
- 앱 아이콘·시작 화면은 `assets/brand`의 전용 생성 이미지를 사용하며 정식 앱과 검사 앱의 배지를 구분합니다. 스토어 등록용 이미지는 별도 준비합니다.

검증 결과와 의존성 경고는 [책 1장](../../docs/book/chapters/01-first-app.md)에 기록했습니다.

SDK 58 업데이트 과정과 최신 검증 결과는 [Expo Go 호환 오류 해결 기록](../../docs/book/chapters/01a-expo-go-sdk58.md)에 있습니다.
